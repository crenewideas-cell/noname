# 联机武将池

## 房间规则

创建房间及等待期间，房主可设置 `characterPool: { packs: string[], banned: string[] }`。
默认使用标准、神话再临、界限突破；快速匹配使用相同固定默认值，自定义组合使用房间。
编辑器支持按包勾选、搜索禁将、导入本机单机或旧联机的启用包与禁将。
导入仅取项目内置包的交集，不读取第三方 `extension` 目录。

规则由服务端保存，出现在房间列表和房间详情。等待期间修改规则会清除全员准备；
开局后禁止修改，再来一局保留规则。客户端本地设置不决定其他玩家的候选池。

进入对局、返回大厅及重新同步需要刷新页面。客户端在刷新前等待 `room.navigate` 确认，
服务端为该成员保留 120 秒的页面切换保护，避免双方同时刷新时误删房间或转移房主。
重新认证、主动离房会解除保护；超时由定期清理收回（清理周期 30 秒）。
普通全员断线、全员退出仍删除房间，切换保护不会在服务端重启后恢复。

## 加载与校验

- `packages/online-protocol/src/character-pool.ts` 是联机允许包的目录，包含目前项目内置的 26 个联机武将包。
- 服务端拒绝未知包、空包列表和非法禁将编号，并去重、规范顺序。禁将上限为 512。
- 房间启动时将规则快照传入 `HostSpec`，由托管引擎写入 `lib.configOL.characterPack/banned`。
- 双方加载相同顺序的内置武将和卡牌定义，以支持跨包技能引用。开局候选仅取房间启用包，牌堆仍为标准牌堆。
- 联机构建编译目录中的全部武将包，包括不在 `moderned_characters` 中的旧入口包；旧包保留 `包名/index.js` 入口。
  不能原样复制这些包，否则跨包源码和引擎内部模块引用可能指向发布产物中不存在的文件。
- 资源错误会列出未注册的 `character:包名` / `card:包名`，规则校验异常单独报告，详细异常保存在服务端日志。
- 托管端在通知玩家入席前检查资源、禁将所属包，并沿用引擎过滤器检查联机禁用、隐藏武将、模式限制。
  同名替换族按一个候选计算，至少保留每席 3 个候选。不满足时返回等待状态并显示具体原因。
- 选将、主公候选、同名版本选择及后续武将列表沿用身份和斗地主现有引擎实现。
- 客户端入席前检查完整资源；正式构建的资源哈希及开发默认 build 标识防止新旧客户端混用。

## 后续增加项目包

先将支持 `connect: true` 的包纳入项目标准 `character` 构建与包注册，再更新共享联机目录。
服务端托管资源和玩家客户端必须从同一版本生成、一起更新。
无需从房主浏览器上传或执行武将脚本；第三方扩展不能仅凭包名绕过服务端目录。
