## 实现

- `noname/util/backgroundTasks.js`：以独立浏览器任务处理协作步骤，每轮 4 ms 预算、128 个排队任务上限。用户请求优先于后台工作，同优先级轮转。支持取消函数和 AbortSignal，空闲回调不可用时用计时器回退。输入后避让 120 ms；等待超过 1 秒时允许有限推进，输入压力下仍每轮只执行一个原子步骤。队列排空释放监听与定时器，页面离开取消；bfcache 暂停并在恢复时继续。
- `LibInit.onfree`：保留回调 FIFO 和回调内部原子性，移除“500 ms 后每 100 ms 执行整个回调”的固定循环。单个回调失败记录错误，后续回调继续。未知扩展回调不能被任意切开，仍可能超过单次预算。
- 菜单：开局仅建立标签和空页；首次打开按用户请求准备，离页、关闭、清理竞技场和切模式取消未开始任务。各菜单使用独立的容器与页面上下文，避免普通菜单和联机菜单共用可变页队列。失败显示重新载入入口；不自动反复执行有副作用的失败构造器。
- 选项中的常规、外观、技能等子页也按需创建；技能选项集合到实际打开技能页才计算，用 Set 查询且不修改 `lib.skilllist`。其它子包已有的惰性构造保留，首次启动不再因 `menu_loadondemand` 尚未写入而展开所有包。`game.syncMenu` 模式保留同步兼容路径。
- 菜单兼容：程序化 `menuTab`、扩展页、控制台和扩展编辑入口同步准备目标页。动态武将/卡牌包在初次打开时从当前注册表读取，打开后的更新回调继续使用。录像数据与保存通知不依赖打开菜单，读取录像时按时间去重，避免重置本局新录像。
- 预备按钮：按单个按钮边界分批激活，保留真实按钮及显式 `activate()` 的同步契约；同一节点不重复排队。关闭/切换页面取消，重开后恢复剩余节点；清理竞技场取消旧批次和旧牌堆等待参数。
- 身份局、斗地主与通用选将布局：自由选将实际点击时才创建目录；移除会在选将结束后迟到的目录预构造。搜索沿用阶段 2 的分批索引、Worker 与取消机制。
- `finishCards` 维持卡牌/技能归一化同步原子执行，仅新增 `rules.finishCards` 计时。继续使用 ContentCompiler 的函数对象 WeakMap 缓存，不改旧 step、包注册、首次发牌或规则顺序。

菜单页的构造器、单个按钮和未知扩展回调仍是不可抢占的原子步骤；4 ms 不能限制某个原子调用本身耗时。已消除未打开菜单和未使用目录的预构造，但首次打开大包、复杂设置或旧扩展页面的耗时仍需最终 profile，不宣称全部长任务消失。
