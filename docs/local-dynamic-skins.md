# 本地动态皮肤

动态皮肤验证扩展已退役，不再注册或加载。原安装目录暂存于 `temp/removed-dynamic-validation/`；原 ZIP 保留。旧验证皮肤选择会在下一次加载本地皮肤时清理。

当前本地素材位于 `apps/core/extension/imports/本地动态皮肤包/`。整个目录（包含清单、播放器副本、绑定元数据及以后新增的包）由 Git 忽略。共享导入代码和渲染适配可以提交，皮肤素材不提交。

## 导入与使用

在项目根目录运行 `pnpm skins:import`，默认读取 `temp/动态皮包/`。也可运行 `pnpm skins:import "D:/我的动态皮包"`，该目录的每个子目录应包含 `catalog.json` 或旧版 `dynamicSkin.js`。导入后重新加载游戏，在已启用的千幻聆音武将皮肤页面选择。

`manifest.json` 保存所有已安装包；后续导入会保留未涉及的已有包。导入不删除源文件。`导入清单.md` 和 `import-report.json` 记录数量、路径修正及待修复素材。

## 按需加载

启动只安装接口，不读取动皮清单、骨骼、贴图或语音。打开某个武将的皮肤页时，才读取小型 `runtime-index.json` 和该武将的 `characters/*.json`，列表不包含完整模型配置。选中预览或局内实际显示已保存的皮肤时，播放器才读取对应的 `entries/*.json`、播放库和素材。未揭示武将不触发加载；关闭预览或隐藏头像会销毁播放器。

同一武将的并发查询合并，已读取列表在本次游戏中复用；失败请求可以重试。未加载的已保存皮肤不会被误删。游离皮肤不进入武将列表，只有明确绑定后才会随武将加载。

以后运行 `pnpm skins:import` 会自动生成这些小型索引。只更新索引和播放器、不重复制整包素材时，运行 `node scripts/index-dynamic-skins.mjs`。完整 `catalog.json` 仅供导入和校验工具使用，游戏不读取它。

开发服务器跳过整个本地动皮目录的文件监听，避免新增大量素材拖慢启动。更新播放器或素材后手动刷新游戏。索引、播放器副本和素材仍统一受 Git 忽略规则保护。

## 归属

- 基础包保留 `dynamicSkin.js` 的明确武将 ID 和共享别名，合并重复皮肤的 `characterIds`。
- 名将杀动皮只绑定该扩展的 `mjs_lumochou`、`mjs_yuji`、`mjs_diaochan`、`mjs_hane`，不因同名而绑定本体武将。
- 无明确 ID 的素材保持游离。中文名、拼音、包中 `aliases` 仅作为原始信息保留，不用于跨角色自动匹配。
- 旧安装保存的手动 `localDynamicSkinBindings` 会被保留；标记为自动猜测的绑定不作为归属依据。
- 若要明确绑定游离皮肤，在源 `catalog.json` 的对应条目设置 `"characterIds": ["实际武将ID"]` 后重新导入。`[]` 表示游离。列表、动态表、资源查询、预览、应用和局内头像都检查归属。

## 校验

`pnpm skins:test` 检查归属隔离、缓存和事件/布局逻辑。

`node scripts/audit-dynamic-import.mjs` 检查可用目录项的模型、图集、贴图、Live2D 参数/动作/表情及语音依赖。

`node scripts/audit-dynamic-models.mjs --quarantine` 使用项目实际解析器检查基础包模型，并在素材目录记录失败模型及其骨骼/图集联合哈希。之后运行 `pnpm skins:import`，不变的失败模型会被隔离；补齐或替换后因哈希变化而重新进入验证范围。原始素材始终保留。

`node scripts/dynamic-import-browser.mjs` 使用隔离的浏览器存档验证武将页面、跨武将拒绝、动态预览及各版本代表模型。它不表示逐一渲染了全部皮肤。开发服务默认使用 `http://127.0.0.1:8081`，可通过 `NONAME_UI_TEST_ORIGIN` 修改。

`node scripts/dynamic-lazy-browser.mjs --shousha` 检查启动零动皮请求、单武将列表、单皮肤详情加载；加 `--timeout` 注入手杀素材清单超时并验证重试恢复。`node scripts/dynamic-lazy-game-browser.mjs` 验证已保存皮肤在对局中按需恢复、暗将不加载、揭示后才加载。`node scripts/dynamic-dev-startup.mjs` 使用临时端口验证冷启动与监听排除，不影响正在运行的开发服务。

基础包默认保留骨骼导出的坐标；不能假设所有素材的人物与背景都具有相同单位、中心或比例，也不能把旧头像参数直接当作骨骼变换。`runtime/composition.js` 保存已核对的构图适配：“魏武东临”使用独立人物层比例，“虎年清明”采用偏左取景。层变换在骨骼约束计算完成后作用于绘制矩阵，不修改根骨骼。保留动画速度和隐藏部件设置，支持旧版 Spine 和新版 Spine 混合图层。Spine 3.6 网格按图集的原始尺寸、裁切偏移和旋转恢复 UV，避免衣袖等相邻部件接缝错位。

基础包使用原生竖版头像框，以同一个比例缩放完整场景并裁切到头像范围；取景优先采用背景画面，不把画外竹叶、粒子等部件纳入边界。不再用灰色模糊底填充基础动皮，也不再将头像框扩展成横框。旧版取景缓存自动失效。没有源缩略图的条目使用文字占位图，选中后播放实际模型。

透明单人物使用完整可见边界，不能从衣服上的不透明矩形推断“背景”；独立背景未满足不透明场景检测时，退回该背景自己的可见边界，而不是整组人物与特效的并集。偏移构图同时应用于预览和局内其他玩家头像。手杀预览的交互按钮跟随静态切换按钮的实际尺寸排列，窗口大小变化后重新定位。

`node scripts/dynamic-proportion-browser.mjs` 检查卢弈两张皮肤和各 Spine 播放路径的代表场景，生成横版场景、竖版头像截图供目视检查，同时验证原始根骨骼比例、原生框标记及窗口变化后的坐标稳定性。实际皮肤页可用 `SKIN_TEST_CHARACTER=luyi`、`SKIN_TEST_TITLE=姝丽风华` 环境变量运行 `scripts/dynamic-lazy-browser.mjs`，同时验证启动零动皮请求和单选加载。

`node scripts/dynamic-case-analysis.mjs` 复现势小乔、曹操两张、神郭嘉及卢弈对照样例，校验源文件与导入文件相同并生成截图、SHA-256 清单与取景信息。`--layers` 分别输出每层；`--native` 用原动画播放器和源头像参数对照（同时应用已确认的网格 UV 修复，避免混淆两个变量）。样例修复不代表全量素材已完成视觉验收；缺文件、骨骼/图集不配套与构图不适配需要分别处理。具体发现见 `docs/dynamic-skin-display-diagnosis.md`。
