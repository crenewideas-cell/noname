# 联机代码静态复核与修复

日期：2026-09-11。仅阅读源码并修复；未运行测试、类型检查、构建、浏览器、容器或公网联调，未分析或修改 `扩展包/`。

## 本次修复

- 会话生命周期：WebSocket 按数据库会话到期时间主动以 4002 关闭；空闲心跳也检查撤销与封禁，封禁以 4003 关闭。握手失败沿用对应鉴权关闭码；版本失败使用独立的 4004。
- 客户端恢复：鉴权失效清理本地账号状态并展示登录入口，封禁与版本失败停止自动重试；关闭旧连接时立即释放引用、拒绝待完成请求，避免延迟回调覆盖新连接状态。
- 托管端输入：只接收明确的选择字段，排除旧引擎 `_sendskill`、`_apply_args` 等控制字段；使用引擎的技能启用条件、次数限制，并检查牌区、目标、数量、候选项以及观星牌的完整性。校验期间临时重建选择上下文，结束时恢复。其他玩家牌的选择按服务端候选列表校验，不再一律当作操作自己的手牌。
- 房间权限：普通房间命令必须对应当前活动席位，离开旧对局后不能再次操作其残留成员记录；旧房间关闭和席位超时通知不会影响账号的新房间。房主转移排除已放弃席位。
- 房间恢复：重启恢复排除已放弃和重复占位成员；结算与实例失败会清除已无意义的恢复截止时间，避免之后误释放账号席位。
- 开局恢复：房间快照增加 `instanceReady`，托管实例就绪后即使漏收 `game.assigned`，玩家也能从 `starting` 房间重新进入，不再互相等待至启动超时。
- 构建模块边界：独立构建的 connect 模式通过共享 `game.startManagedGame()` 加载适配器，避免它和本体大厅各自打包一份会话 store，导致离房/返回时重复连接或丢失玩法状态。
- 原生入口：桌面使用无 Node/preload/remote 能力的独立联机窗口；Android 使用没有 Capacitor/文件访问桥接的独立 WebView。两者直接打开服务器的同域客户端，HTTP API、Cookie、WS 使用同一来源，无需跨域 Cookie 或放宽平台来源校验。

这些是源码层面的修复结果，不代表运行验证已通过。

## 当前使用 HTTP 和 IP

根据用户最新要求，当前部署不依赖 HTTPS、证书或域名；此约定取代早期交接中关于必须配置域名和 TLS 的部署步骤。

`deploy/online/.env` 使用实际服务器 IP。例如下列 `192.0.2.10` 只是示例，必须替换：

```dotenv
PUBLIC_PORT=80
PUBLIC_ORIGIN=http://192.0.2.10
ONLINE_BUILD_ID=online-phase3-v1
```

网关 `Caddyfile` 监听 `:80`，Compose 只映射 `PUBLIC_PORT` 到该端口，不启动自动证书流程，也不要求 `PUBLIC_HOST`。若映射端口为 8081，则同时设置 `PUBLIC_PORT=8081` 和 `PUBLIC_ORIGIN=http://实际IP:8081`。数据库、worker、平台与文件服务不作为对外入口。

浏览器直接打开 `http://实际IP:端口/index.html`。构建本地桌面/Android 使用的本体资源时，指定 `VITE_ONLINE_ORIGIN=http://实际IP:端口`，玩法卡片会打开同域联机窗口；该设置属于发布配置，玩家不需要逐人填写 IP。未配置时，本地壳会明确提示缺少入口，而不会把本地文件服务误作联机 API。网页资源和服务端继续使用一致的构建标识。Android 源码已经允许 HTTP 流量。

本次没有实际服务器 IP，因此没有填入真实部署地址或执行部署；`.env.example` 保持示例值。
