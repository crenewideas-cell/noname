# 联机技能提交修复与复测

本次依据 2026-09-12 服务端日志中 `HOST_CHOICE_REJECTED (chooseTarget/chooseTarget): Cannot destructure property 'range' of 'info' as it is undefined` 排查。该记录表示服务端拒绝了一次目标选择，截图中的全屏提示不能单独证明 WebSocket 断线。

## 已修复

- 谋郭嘉天妒：`chooseUseTarget` 通过事件 `_get_card` 提供虚拟锦囊，目标验证现在与引擎界面一样使用 `get.card()`。保留正常目标和距离限制，也覆盖其他通过该事件使用虚拟牌的技能。
- 谋曹丕行殇、放逐：选项只传稳定的数字索引，效果、消耗、目标过滤和后续内容从已安装技能定义重建；不再把含函数的效果对象作为客户端结果传回。同步处理仍保留在 TW 包中的旧版 `twxingshang`、`twfangzhu` 定义；它们与当前 TW 谋曹丕的 `twsbxingshang`、`twsbfangzhu` 是不同技能。
- 文字选项弹窗：兼容 `textbuttons()` 创建的无 `_args` 按钮，保留选项标识、展示文字和禁选状态，可重建远端及重连弹窗。
- 联合选择：支持 `chooseButtonTarget` 的弹窗和结果；按按钮、牌、角色的顺序重建选择上下文，让角色过滤正确读取 `ui.selected.buttons`。适用于谋张辽登锋、TW 谋曹丕行殇分配牌、虞翻纵玄等使用此流程的技能。界面辅助按钮不会被误当成必须提交的 `chooseControl` 结果。
- 按钮：联机技能按钮显示可发动状态和固定使用次数的剩余次数，支持键盘操作与悬停说明；长文字选项可换行、滚动，区分可选和不可选状态，控制区支持换行。
- 日志：选择拒绝增加来源事件/技能标识，方便关联后续问题。

## 本地验证

在项目根目录执行：

```powershell
pnpm test:online-skills
```

测试启动独立 Vite 服务及无头 Chromium。Windows 默认使用已安装的 Chrome；其他路径可设置 `CHROMIUM_PATH`。输出位于 `output/online-skills/`，包含 JSON 报告、桌面和横屏截图。

17 组回归覆盖天妒目标、行殇/放逐各可选效果、弹窗传输重建、按钮与目标联合选择、卡牌分配、武圣、龙胆、奇袭、国色、仁德、制衡、倾国、非法技能和函数拒绝、取消与异常后的上下文恢复。另逐个初始化 2,551 个联机加载武将定义，完成 1,300 余次主动技能入口检查，未发现异常；具体次数随初始化技能变化，以每次 JSON 报告为准。

上述广泛检查只覆盖给定初始场景的发动条件，不代表所有技能、装备、模式和多回合组合已实战穷举。联合选择回归验证相同事件结构；未逐局执行所列武将的全部技能内容。

真实托管引擎冒烟测试命令：

## 更新与公网复测

这次修改涉及规则代码与客户端展示，服务端和客户端需要使用同一个新构建。按现有 `deploy-online.cmd` 更新服务器，并重新分发包含新 `online-client` 资源的客户端。单独重启服务器或继续使用旧安装包不会更新这些代码。本次代码修复不自动发布到公网服务器。

复测时优先确认：

1. 谋郭嘉天妒弃两牌，选择决斗等需要目标的锦囊，提交目标后继续结算；再测无目标锦囊及下一次转换技判定。
2. 谋曹丕达到不同“颂”数量后分别发动行殇、放逐，包括放逐的两个目标、行殇的阵亡目标、使用次数耗尽和取消。
3. 谋张辽登锋、TW 谋曹丕行殇或虞翻纵玄的联合选择；选择中恢复房间，确认选项与目标仍对应。
4. 在 Xshell 保持 `docker compose logs -f --tail=200 --timestamps platform`，记录问题时刻、武将、技能和操作步骤。若出现新异常，提供前后完整日志及构建号，便于继续补充确定性回归。
