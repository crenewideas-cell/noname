# 第二阶段交接：好友、匹配、自动恢复与斗地主

日期：2026-09-11。依据：[三轮开发方案](../public-online-three-round-plan.md)与[第一阶段交接](phase-1-handoff.md)。

本轮完成第二阶段源码开发，按用户要求不运行测试、构建、浏览器联调或公网验证。扩展包内容不在本轮分析和构建范围内。本轮历史协议构建标识为 `online-phase2-v1`；当前协议、平台与公网静态资源请使用第三阶段的 `online-phase3-v1`。

第三阶段已继续开发；当前部署和运维说明以[第三阶段交接与部署说明](phase-3-handoff.md)为准。本文件保留第二阶段的功能范围记录。

## 本轮开发范围

好友关系、申请、删除、屏蔽和在线状态已持久化到 PostgreSQL。玩家可以使用公开玩家码查找其他账号；屏蔽关系优先于好友和邀请。好友房内可以向在线好友发出定向邀请，邀请有效期两分钟，接受时再次检查好友关系、房间容量、房间状态和当前占用，不能通过旧邀请覆盖当前房间或匹配状态。

快速匹配按 `modeId + preset + capacity + region` 分队列，采用先入先出。首版为单人队列；身份支持 2/4/6/8 人，斗地主支持 3 人。人数不足继续等待，不创建假玩家。匹配成功后进入 15 秒全员确认窗口；取消、拒绝、超时、掉线、服务器容量不足和创建失败均由服务端回收或回队列，分配成功后复用已有房间和托管实例流程。

自动恢复使用指数退避和抖动，连接票据仍是一次性短期票据。进行中席位默认保留 120 秒，可由 `RESUME_GRACE_MS` 调整。服务器为每个席位递增连接代次，旧连接、旧代次和异步处理完成后失效的连接不能继续提交动作。刷新或重新进入时，平台依据 active room 返回房间和实例，客户端重新加载对局展示。

恢复快照包含当前场上状态、自己的完整手牌、其他玩家的牌背、可见装备/判定区、身份可见性、当前阶段、轮数和剩余牌数。其他玩家未公开的身份、手牌内容、获得标签和特殊区域会在发给该账号前隐藏。恢复期间新的引擎消息暂存，快照确认后再按顺序发送；快照超时则当前席位继续托管。

每个客户端选择都带服务端生成的 `token`，动作还带 `actionId`、`turnId` 和 `expectedRevision`。服务端校验席位代次、当前提示、截止时间、手牌所有权、目标范围、技能权限、牌和虚拟牌来源，并对重复 actionId 做幂等处理。客户端过期回调不再借用下一次选择的令牌。

第二阶段开放标准身份和标准斗地主。两者均只使用 `standard` 武将/卡牌包，不加载扩展、不开放旁观和自定义规则。斗地主服务端固定三人普通规则，房间、匹配、结算和恢复与身份共用同一套房间和托管实例生命周期。

## 配置与部署

开发或部署平台时统一设置：

```text
ONLINE_BUILD_ID=online-phase2-v1
MATCH_REGION=default
RESUME_GRACE_MS=120000
```

公网静态资源使用 `pnpm build:online`，产物仍只来自本体依赖图，过滤扩展目录。平台运行在 `8082` 内部端口，玩家通过同域 HTTPS/WSS 访问；平台、数据库、静态资源服务和 Chromium 执行器不直接向公网开放。Compose、Caddy、Chromium 沙盒和第二阶段环境变量见 `deploy/online/`。

第二阶段数据库迁移在平台启动时幂等执行，创建好友、屏蔽、邀请表，并保留已有账号、会话和结算数据。平台只允许一个调度进程持有数据库 advisory lock；活动房间仍依赖内存调度，平台整体重启会关闭失去执行实例的活动对局。

## 用户验证顺序

以下只作为交付后的验证清单，本轮没有代为执行：

1. 用两个账号互相发送好友申请，分别验证同意、拒绝、撤回、删除、屏蔽和解除屏蔽；退出后重新登录确认好友关系仍保留。
2. 在等待房间向好友发邀请，验证好友能看到两分钟倒计时并加入；验证陌生账号、被屏蔽账号、满房、离房和过期邀请不能切换当前房间。
3. 使用三个真实账号进入斗地主三人匹配，确认人数不足时持续排队；全部确认后进入同一真实房间，完成一次标准对局和结算。
4. 使用身份玩法进行匹配，验证 2/4/6/8 人能力与房间规则一致；取消匹配后不能突然进入房间，确认窗口拒绝或超时后状态回到可匹配状态。
5. 对局中拔网、刷新页面、短暂关闭标签后重新进入大厅，确认保留窗内回到原房间和原席位；检查自己的手牌、公开信息、身份可见性、当前行动和服务器托管状态。
6. 在恢复和重新连接期间打开第二个窗口，确认旧窗口或旧动作不能继续控制同一席位；恢复完成后过期选择不能重复出牌。
7. 关闭房主浏览器，确认其他玩家和服务器托管实例继续；房主恢复或席位超时后，分别确认恢复和托管结算路径。
8. 以手机窄屏和桌面宽屏查看大厅，确认好友、匹配、创建房间、离房和恢复按钮均可见，原有背景和玩法卡片仍保留。

## 已知交接边界

本轮没有运行时证据，因此公网可玩目标仍需用户实际部署和验证后确认。浏览器 Chromium 依赖需要在目标环境安装；首次部署的实例上限和资源配置仍需结合服务器实际容量调整。平台重启后的进行中对局不承诺无损恢复；服务端会明确结束失去执行实例的活动房间。

当前匹配不支持好友组队排队，好友对战通过私房邀请完成。当前没有旁观、自定义卡池、扩展玩法、段位匹配或跨区域匹配；未开放玩法仍回到单机逻辑或显示未开放状态。
