# 动态皮肤通用显示排查（2026-09-25）

本次故障确实包含程序的通用问题，不能把“骨骼可以加载”当作显示正确，也不能统一归因于素材损坏。本轮修复覆盖导入时模型选择、图层坐标、取景、列表预览和交互按钮；未修改源贴图或武将绑定。

## 最新一轮：张昌蒲背景断层、侧向取景与重复放大

本轮故障在本地动皮导入和播放器适配层，未发现这四个样例由千幻聆音的界面层或骨骼文件损坏导致。没有添加按武将、皮肤名称或 ID 的生产分支，也没有修改源图、骨骼或动画内容。

- **战场绝版两个版本：云雾扩大了背景边界，又触发头像放大。** 真正的连续底图高度约 636，框外云雾却把背景范围撑到约 1360。只在原背景拟合失败、且没有可识别的人脸矩形时，用前景不透明主体验证背景矩形；要求覆盖主体至少 70%，并拒绝切掉超过 2% 上方主体像素的候选。补救成立时，才撤销基于错误背景范围推断的头像放大。已有完整模型校准、图层校准和正常背景取景保持优先。
- **静谧轻舟：把躯干骨骼当作脸，覆盖了源配置的侧向取景。** 对具有明确框外横向焦点的配置，零面积骨骼点不再覆盖原焦点；真实人脸仍可参与定位。紧凑命名补救同样不把零面积躯干点当脸。修复后头部进入画框。
- **寄情山水：前景和背景里的头发使用不同坐标单位。** 六个共有部件提供了直接证据：校准比例约 1.898，旧推断却放大到 3.333。导入器比较网格拓扑、UV、纹理尺寸比例及多个动画时刻，计算等比变换；在播放器中以校准结果替代旧的推断放大。

**控制适用范围：** 同名几何能够对齐，不等于应该改变已有构图。校准只替换已有的推断放大，要求能识别人脸、至少三个共有部件且来自不止一种名称系列、共有几何未覆盖几乎整个人物、变换不增大人物且不改变姿态角度。相同部件在 1/30、0.5、1 秒的位置误差必须小于 0.01，变换必须稳定。整个人物的另一种姿态、单一特效/伴随物序列、无法确认人脸等情况保留原规则。最终全包仅 5 项采用新校准；批量候选的前后画面对照曾暴露过范围过宽，已收紧后重新验证，不能引用中间的 21 项作为最终结果。

对于已证明两层单位不同、但不满足安全构图条件的候选，索引保留 `layerCoordinateMismatch` 证据，阻止背景补救把现有图层变换清零。只有几何证明与最终构图都成立才应用新变换；“未采用校准”不能被误解为“原始坐标相同”。

验证记录位于 `output/dynamic-zhang/`：41 项单元测试；本轮四个样例的两种尺寸及其余校准条目共 12 个视图，在 0、1、3、5 秒检查；31 个既有正常样例和排除候选的修改前后对照，取景和图层变换保持一致；原九个样例共 18 个视图、四个延迟首帧检查，以及真实游戏里的缩略图、按钮、文字和动态/静态往返切换。四个安装包的 20 份相关运行时文件与源码一致，缓存版本为 `portrait-v13`。源素材字节核对见 `after.json`。这些验证不等于全部数千个皮肤、全部动画逐帧验收。

复现入口为 `scripts/dynamic-zhang-regression.mjs` 和 `scripts/dynamic-zhang-preservation.mjs`；后者使用 `output/dynamic-zhang/baseline-runtime` 中保存的本轮修改前运行时，对照报告为 `controls.json`。四个用户样例的最终画面见 `result.png`。

**为什么反复出现：** 源包混合了不同骨骼版本、头像/完整场景模型、坐标单位和动画约定；本地适配先前把配置标记和粗略边界当成通用构图依据，例外不断暴露。前几轮修复对部分推断规则推广过早，且加载成功、几何一致、少量静帧并不能证明最终构图正确。责任不能笼统归给千幻聆音；本轮应归于本地导入/播放器的兼容策略。现在分别校验加载、图层坐标、实际取景及动画时序，并用旧版本对照约束新增规则。

## 上一轮：头像裁切框、独立人物与天空循环

三种现象属于不同的公共展示边界，未修改贴图、骨骼二进制或图层顺序：

- **极略三国神郭嘉：忽略了素材声明的头像画框。** 资源有配套静态背景、头像专用动画和覆盖人物插槽的矩形 clipping。旧相机却包围了框外烟雾，导致人物纹理内部切边在画框中央露出。现在加载明确声明且可解码的本地背景；仅对单骨骼、存在头像动画、唯一矩形人物遮罩的组合采用该遮罩作为视口。原遮罩保留。背景与动态人物合成到同一个输出画布，缩略图也捕获这一画布；非矩形、多个遮罩和无配套背景的资源不套用该规则。
- **透明全身人物：错误使用场景铺满缩放。** 没有独立背景、没有静态背景且采样不构成完整不透明画面的单模型，改用完整容纳并保留 3% 动画余量。有背景的场景继续铺满，内嵌不透明画面的模型也保留原策略。
- **明良千古天空：出场镜头被循环当作背景待机。** 源配置将背景指定为 `ChuChang`，动画本身会在 3.33 秒内缩放，而同一骨骼实际提供稳定的 `BeiJing`。现在仅当背景层声明明确的出场动作且确有稳定背景/待机动作时选择后者；其他自定义动作和前景动作保留。人物动画继续运行。紧凑前缀的人脸识别只在原规则未识别人脸、且旧画框确实会裁到新识别的人脸时补救；已正常的取景不重新居中。

验证：38 项单元测试；15 个已正常样例分别运行修改前和修改后代码，对照取景及图层变换；三个新样例在 360×600、240×360 下检查；天空采样 0、1、3.4、5、7、10.2 秒，背景范围恒定且全画框不透明，前景动画时间正常推进；原九个样例的 18 个大图/缩略图检查及四个首帧回归通过。真实游戏验证神郭嘉配套背景、缩略图、交互按钮、文字边界和静态/动态切换。结果在 `output/dynamic-feedback/regression.json`，回归入口为 `scripts/dynamic-feedback-regression.mjs`；对照使用修复前保存在该输出目录中的运行时代码。缓存升级到 `portrait-v12`。这些检查覆盖代表性样例，不宣称已逐帧验收所有皮肤。

## 上一轮：谋甄宓缩放、加载首帧和底部文字

这轮定位到三个通用问题，修复仍在模型索引、播放器加载时序和公共预览组件中，没有添加按皮肤 ID 的修正：

1. **完整模型识别漏掉单腿和数字命名的导出。** “洛神御水涩”只新增一个明确命名的腿部附件，“临水照花”主要使用数字附件名；原规则要求两个新增腿/脚，因此二者继续使用头像裁切模型并放大。现在增加完整几何覆盖校验，要求原附件匹配至少 90%、新增至少两个附件、坐标配准后的宽或高扩展超过 10%，同时保留 UV 不缩小、动画与图集完整和配准误差检查。数字纹理名称本身不足以判断人物：还需人物骨骼链，或插槽绑定的骨骼也采用一致的数字命名。通过此分支的完整模型保留配准比例，不再叠加头像放大。
2. **加载期间的取景采样画布提前可见。** 原生渲染器先生成临时采样画面，随后异步加载构图模块，再调整为最终取景；用户看到的约半秒缩图正是这个中间状态。播放器在完成取景和最终尺寸绘制前隐藏画布，外层也等到 ready 消息才显示 iframe。回归测试在该异步边界人为增加 500 毫秒延迟，逐帧检查中间画面始终隐藏，首个可见帧使用最终视口尺寸。
3. **底部把内部检索键直接当标题，并按文字长度扩大容器。** 显示名称改为“皮肤名 · 武将名”，完整检索键单独保存在数据属性中，动态/静态切换继续使用该键。文字栏的左右边界约束在画框内，长名称最多两行，来源栏单行省略；交互预览也使用同一布局，不再写入超出画框的固定宽度。

真实游戏验证覆盖两种窗口尺寸、超长标题、交互按钮、动态/静态往返切换和缩略图缓存。首帧回归覆盖两个甄宓模型、神郭嘉红色版本及 PIXI 渲染样例。34 项单元测试通过。最终基础扩展有 190 项通过完整模型校验，新增几何分支为 41 项；44 个新增及历史样例完成渲染与源文件字节核对。逐项记录见 `output/dynamic-first-frame/report.json`、`output/dynamic-import/lazy-after.json`；模型抽查和源文件字节核对见 `output/dynamic-cases/analysis.json`。四个已安装皮肤包的相关运行时文件与源码一致，缩略图缓存版本更新至 `portrait-v11`。批量加载检查不等于数千个皮肤的全部动画帧均已人工验收。

## 上一轮：黄月英、王异、吴国太的九张截图

已复现并修正三类通用缺陷：

1. **把单块背景纹理误认为整幅背景。** 智飞巧慧的背景由上下纹理块合成，旧规则只取到下半块；巾帼战野也会选中前景块。现在先渲染背景层，依据合成后的像素计算取景。半透明场景中的灯笼、天空小块不能单独决定画框：使用人物位置和背景覆盖范围验证候选矩形，未通过时回退到完整背景范围；隐藏图层不参与背景候选。Spine 3.6 和 PIXI 使用相同规则并保留各自 Y 轴方向。
2. **完整模型增加腿部附件，却未增加旧附件的 UV 面积。** 旧校验因此漏选完整模型。现在同时识别至少两个新增腿/脚附件，要求原附件匹配率至少 80%、没有 UV 范围缩小、动画兼容、图集页齐全，且同名同 UV 部件的统一坐标变换残差不超过原模型对角线的 2.5%。名称别名已匹配的部件不算新增。此类模型采用校验所得坐标变换，不再叠加半身头像放大。原 UV 扩展分支仍保留更严格的 90% 匹配要求。
3. **没有面部名称的数字骨骼，及带主体前缀的头部被漏识别。** 现在利用主体附件的共同前缀识别头部；数字命名资源可使用人物骨骼链定位，排除前景树叶等骨骼。没有添加按武将或皮肤 ID 的位置补丁。

基础扩展共 149 项通过完整模型校验，其中 115 项为新增肢体分支。九个截图样例对应 18 个大图/缩略图检查，验证人物定位在框内、画面覆盖率超过 97%，四个相关条目的完整腿部附件处于显示状态。另完成 157 个完整模型和历史样例的渲染与源文件字节核对、10 个上一轮回归样例、34 项单元测试。批量可加载不代表每个动画帧都已人工验收。

真实游戏检查王异的缩略图、按需加载和交互按钮；启动时皮肤包请求为 0。缩略图缓存升级到 `portrait-v10`，重新加载游戏后自动生成新图，无须手工逐项调整。

复现入口：`scripts/dynamic-body-framing-regression.mjs`，结果在 `output/dynamic-body-regression/report.json` 和同目录截图；扩展样例在 `output/dynamic-cases/analysis.json`。下文的 32 项、30 项与 v9 为前一轮记录，以上述最新验证为准。

## 本轮新截图的定位与修正

- 严夫人“长乐未央”和“长乐未央涩”的骨骼字节相同，主要是贴图版本不同；原运行时直接依据 shizhounian 标记选择放大分支，造成不同构图。现在导入时对前景、背景骨骼及图集元数据做 SHA-256 校验，并比较动画、位置、比例、角度、速度及隐藏插槽。完全相同的组合共享 avatarPresentation；不同模型、不同配置不继承。显示和完整模型选择使用这份已核验的元数据。完整场景 daiji 不直接套用紧凑头像 daiji2 的放大逻辑。
- 三个缩到角落的神郭嘉版本，目录内实际提供配套 BeiJing 骨骼，但源配置没有声明。导入索引现核验同目录、完全对应后缀的 XingXiang / BeiJing 配对，要求二进制完整解析、背景动画存在、所有图集页齐全；不跨目录猜测。全包补齐 7 项，记在 completed-backgrounds.json。背景参与合成后，相机使用背景绘画范围，不再把远处光效当人物尺寸。
- “怀曦赴煌”使用 r-tou 这类面部命名，原定位规则遗漏；还补齐带连字符的背景命名。面部识别限制人物/头部前缀，不能把 xiongmao3_tou 这类动物头当作主角。回归包含人物、动物同时出现的情况。
- 静态“虎年清明”顶部矩形来自 CSS 同时叠放皮肤、原武将图和剪影；透明部分漏出了另一张人物图。兜底改为可见时逐个尝试加载，成功后只保留一张图，并防止过期异步结果覆盖当前选择。矩形预览的透明顶边仅延展当前图片自己的背景条带，不叠加其他人物。
- 首次 RAF 回调时间戳可能早于加载完成时记录的 performance.now，原逻辑出现负动画时间。3.6 和 4.2 播放器均限制增量不小于零，避免初始状态回退。
- 选择卡片后将其滚入可见范围，让缩略图按需队列能够工作；缓存版本更新为 portrait-v9。交互按钮继续在静态模式隐藏，在动态画框内定位。

上述修正没有修改单个皮肤贴图，也没有添加按皮肤 ID 分支。不能据此宣称所有解析器或数千套素材绝无问题；本轮截图已复现的主要原因在配置补全、构图和图片叠加链路。

本轮验证：30 项自动测试；32 个完整模型与 8 个历史样例的画面对照；另有 10 个新回归条目（包括 7 个自动补齐背景），检查面部位置、画面覆盖、动画时间、相同骨骼的取景一致性；16 类格式/版本组合加载通过。实际游戏验证神郭嘉“倚星折月血魔”、神荀彧“怀曦赴煌”及静态“虎年清明”，包含缩略图、缓存、1440×900 和 1100×720 的按钮位置。启动动皮请求和已载入条目均为 0。素材及未来导入包的 Git 忽略仍有效。

## 前期修复保留

1. **头像裁切模型被当成完整场景。** 一些包同时提供 `daiji2` 头像网格和 `daiji` 完整网格，前者头发、披风本来就被裁掉。导入索引现比较附件对应关系、UV 覆盖及同名部件的世界顶点，要求对应覆盖率至少 90%、覆盖范围增加且没有缩小，并检验统一坐标变换的残差。满足条件才采用完整模型；保留原模型信息和变换，贴图不重画、不拉伸 UV。当前 32 项满足条件，记录在各本地包 `scene-variants.json`。未通过校验的候选保留原模型，不凭文件名强换。
2. **完整模型与头像模型的原点、单位不同。** 从相同部件计算等比缩放、旋转和平移，校验后与原图层变换合成。修改发生在骨骼外层，不改骨骼层级或网格。原先 `composition.js` 中两个按皮肤 ID 设置的构图例外已删除。
3. **背景识别和镜头取景不完整。** 识别带前后缀的背景名称及纵向底图，防止把小装饰当作背景；重复底图区分相邻平铺与重叠副本，使用对应的绘画范围。宽画幅利用原头像配置中的横向焦点取景。透明窄边按同一比例裁切，保留 Spine 与 PIXI 的 Y 轴差异，稀疏人物不会被放大到某块衣服。
4. **列表上的文字 SVG 是占位图。** 可见动态卡片现按需渲染真实缩略图，单一队列只保留一个临时播放器；生成后显式释放渲染资源，图片写入 IndexedDB。再次显示直接读缓存。缓存键包含运行时版本、目录修订和模型选择，重新导入会更新缓存。关闭页面或滚出可见区会取消不再需要的工作。
5. **静态露头图的透明顶边被放入矩形卡框。** 在列表缩略图和矩形静态大预览中延展第一段不透明背景条带，原图和人物叠层保持原样；不再露出深色空带，也不裁掉头饰。
6. **交互按钮读取隐藏控件的位置。** 静态或未就绪时隐藏按钮；就绪后依据实际画面与可见切换按钮定位，向画框内留白，随尺寸改变重新计算。

之前修复的透明度混合仍保留：WebGL 纹理上传与 Screen/Additive 绘制使用一致的预乘规则，并覆盖 ImageBitmap、纹理重传和显式预乘素材。否则透明光效会出现白色断带。

- `node scripts/dynamic-import-browser.mjs --render-only`：16 类格式/版本组合可播放；此项只证明播放链路可用。
- `node scripts/dynamic-case-analysis.mjs --variants`：对 32 个采用完整模型的条目及 8 个用户反馈样例做实际画面对照，记录在 `output/dynamic-cases/`；同时核对加载文件与原包内容一致。
- `scripts/dynamic-lazy-browser.mjs`，分别使用 `shen_huatuo/五灵济世`、`shen_lusu/青牛化圣`：动态缩略图有真实图片；新加载器可直接复用持久缓存，未产生动皮请求；静态模式按钮隐藏；1440×900、1100×720 下交互按钮位于框内。
- 上述实际游戏启动中，动态包请求数与载入条目数均为 0。加载模型发生在使用皮肤或卡片进入可见区后。
- 本地包和未来包的 Git 忽略规则继续有效。

此前对 3,152 个 3.6 模型、五个动画时刻的骨骼与约束运算对照仍有效，共 59,438,146 个坐标值与官方 3.6 运算核心一致。对照复用了二进制读取器，因此这不等于独立证明解析、贴图和最终画面全部正确。

本次验证以通用规则、批量模型及用户反馈画面为依据，没有逐帧人工验收全部数千个皮肤。缺失素材的 54 项继续按导入清单隔离，不伪造缺失部件。
