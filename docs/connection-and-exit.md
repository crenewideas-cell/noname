# 退出与联机改进说明

本次范围为游戏本体、桌面/移动端退出入口、局域网房主及独立大厅服务。扩展包及其内容不作为分析、修改对象。依照需求，未运行测试、构建或游戏验证；以下为源码实现说明，不代表已通过验收。

## 退出与界面

- 工具栏退出入口独立固定在右侧，保留两组原有按钮、滚动及主题样式。
- 对局操作弹窗保留继续、重新开始和返回主界面，新增退出程序，等待引擎数据库写入结束后调用平台退出接口。
- Electron 调用应用级 `app.quit()`，替换只销毁当前窗口和退出渲染进程的实现；关闭窗口后清理内置文件服务，超过 5 秒仍未完成则结束应用。未取得单实例锁的进程不再启动文件服务。
- Android 沿用原生退出接口，并将 Promise 返回给退出弹窗处理失败。普通浏览器如拒绝关闭标签页，会明确提示手动关闭，并恢复操作按钮；网页没有权限结束整个浏览器进程。
- 联机输入框、连接按钮、断线弹窗使用现有金棕色风格；输入框适配窄屏，补充键盘操作、焦点样式及可访问状态提示。

## 已发现的问题及实现

| 原问题 | 本次处理 |
| --- | --- |
| 地址解析异常可能逃逸，空地址无结果，重复连接干扰回调 | 统一解析 WS/WSS、IPv4、带括号或裸 IPv6，拒绝无效协议、凭据、片段和空白；隔离旧连接回调；增加取消操作 |
| TCP 连接成功被当作联机成功，错误服务会一直等待 | 收到 `opened` / `roomlist` 才通知连接成功；建立连接和首个游戏协议响应共用 12 秒期限 |
| HTTPS 页面误用 WS | 默认选择 WSS，拒绝显式不安全连接；保留无协议地址的传统 8080 默认端口 |
| 断线直接刷新，用户无法判断发生了什么 | 展示恢复弹窗，可主动重连原服务器或返回/退出；重连保留原玩家身份及房间信息，不循环刷新 |
| 进行中且禁止旁观的房间阻止原玩家重连 | 大厅允许请求到达房主，房主负责验证原玩家身份和旁观权限 |
| 只凭玩家 ID 即可接管断线席位 | 每个服务器地址保存独立的随机重连凭据，房主仅在内存中保存凭据；重连同时验证玩家键和凭据，拒绝顶替仍在线的连接 |
| 未完成身份握手即可调用房主命令 | 握手 10 秒期限，首个命令必须为 init，后续命令须已获房主准入；禁止重复 init |
| 入房失败仍写入 room，重复创建可覆盖房间 | 检查完成后才绑定房间；拒绝重复建房/入房，等待房间核对容量；返回明确失败原因 |
| 房主退出后残留 owner / room 引用 | 通知成员并关闭对应连接，删除成员关联与房间；清理中继映射和定时器 |
| 无限消息和缓冲导致资源耗尽 | 文本消息限定、命令白名单及参数校验、消息大小上限、连接数上限、令牌桶限流、发送缓冲限制 |
| 心跳无法及时清理死连接 | 大厅与局域网服务使用 WebSocket ping/pong，每 30 秒检查；无响应时 terminate，浏览器自动响应控制帧 |
| 每次成员变化立即全量广播 | 大厅成员/房间变化合并为 100 毫秒一批，保留现有消息格式 |
| 技能同步限流时间只在第一次写入，请求成功后仍留超时器 | 每次有效请求更新时间；成功、失败或断线立即清理请求和超时器 |
| 大厅停机可能持续等待连接关闭 | 发送关闭通知，3 秒后终止未关闭连接；复用启动/停止中的 Promise |

## 独立大厅配置

`packages/server` 的程序接口支持 `host`、`allowedOrigins`、`maxConnections`、`maxConnectionsPerIp`、`maxPayload`、`maxBufferedAmount` 和 `messagesPerSecond`。CLI 对应环境变量如下：

| 环境变量 | 默认值/含义 |
| --- | --- |
| PORT | 8082；仍支持 --port / -p |
| HOST | 未指定时沿用 ws 默认监听地址 |
| ALLOWED_ORIGINS | 逗号分隔的浏览器来源白名单；默认不限制，未带 Origin 的原生连接可用 |
| MAX_CONNECTIONS | 1000 |
| MAX_CONNECTIONS_PER_IP | 32；共享出口的部署应按实际人数调整 |
| MAX_PAYLOAD | 2097152 字节 |
| MAX_BUFFERED_AMOUNT | 8388608 字节 |
| MESSAGES_PER_SECOND | 300；每连接令牌桶上限及每秒补充量 |

局域网房主仍使用 8080 端口，消息上限 2 MiB、连接上限 64、每连接每秒 300 条。浏览器客户端发送缓冲上限 8 MiB。上述默认值需要通过实际对局负载验证和调整。

## 兼容性与架构边界

既有消息名称和参数位置保持兼容，重连凭据为新增字段。更新后的房主允许旧客户端首次进入，但旧客户端没有凭据时无法恢复席位；要使用受保护的重连，应同时更新房主和玩家客户端。连接丢失后的恢复依赖原房主、原房间仍然存活；房主退出或大厅重启不会恢复内存中的对局，也没有实现房主迁移。

现有架构仍是大厅中继与房主执行游戏逻辑，包含已有的远程函数传输机制和本地玩家键。此次没有将其改造成权威专用游戏服务器、账号认证系统或持久化事件日志，也没有提供横向扩容、可靠消息重放或跨版本对局恢复。不能把这些基础加固视为完整的生产系统认证。公网 WSS 仍需部署端配置 TLS 证书与反向代理；来源白名单不能替代身份认证。

退出生命周期参考 [Electron app 官方文档](https://www.electronjs.org/docs/latest/api/app)。心跳、强制清理及载荷控制参考 [ws 官方说明](https://github.com/websockets/ws#how-to-detect-and-close-broken-connections) 和 [ws API 文档](https://github.com/websockets/ws/blob/master/doc/ws.md)。
