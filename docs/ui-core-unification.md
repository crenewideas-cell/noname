# UI 与核心逻辑统一

## 当前代码边界

内置 UI 使用的 `noname` 引擎是唯一规则来源。当前工坊的墨金、霁蓝、青玉、如真似幻、手杀标准 UI 都通过本体执行选将、选牌、技能、出牌、响应、伤害、护甲、拼点、观星、AI 和胜负结算。

普通工坊套装仍由 `schema.js` 校验外观配置及资源，由 `runtime.js` 输出 CSS，不执行导入 ZIP 的程序。

手杀标准 UI 不再执行九个旧模块的 `precontent/content`，也不加载 `core-ui.js`、`junba.js`、`doudizhu.js` 或旧技能程序。`native-runtime.js` 只准备登录、大厅与资源；`native/presentation.js` 装饰本体节点，不替换原型、事件内容、规则过滤器、技能、AI 或点击处理器。国战的选将数量、势力校验、确定和取消均交给本体，不再改写选择事件。

如真似幻不再注册 `rankingContent` 或运行旧设置/皮肤扩展。大厅、模式页面、武将图鉴保留；武将皮肤、设置入口接入本体服务。

## 大厅的数据与动作

`sceneContext.js` 给大厅提供独立配置草稿和武将元数据副本。大厅拿不到本体事件、技能、角色原型、游戏循环和联网方法。修改草稿、翻页、动画或旧源程序中的辅助赋值不会覆盖本体对象。

开局通过显式入口提交当前选择的模式及本体配置表支持的子模式、人数。固定人数模式忽略源界面多余的人数字段。不支持的子模式报错。昵称和武将包启停的明确操作使用本体保存接口；其它旧配置保存在套装自己的设置中，不投影到全局配置。

这是项目内受信任 UI 的接口边界，不是任意 JavaScript 的安全沙箱。通过普通扩展安装器安装的代码扩展仍属于规则/功能扩展；不能仅改名为“UI”就保证它不修改规则。新 UI 必须使用这里的展示接口，不应引入旧扩展加载器。

## 展示迁移的可见变化

- 登录和 PIXI 大厅继续使用原素材；对局外观重新适配本体节点。
- 选将、技能交互、拼点、观星和装备选择使用本体控件及规则，旧扩展的专用交互程序不再执行。
- 卡面、武将框、体力、菜单、按钮、字体和指示线由展示层处理；扩展自带卡图和多属性卡面保留本体解析结果，隐藏牌不显示自定义正面。
- 旧动态皮肤加载器、技能改写型特效和旧换将/换牌程序退出运行链，皮肤入口使用本体皮肤服务。旧效果未逐一按原样复刻；不能据此声称与旧版手杀 UI 像素级、动画级一致。
- 结算只读取本体结果及已有统计。附加统计面板不定义新的胜负、奖励或排位规则。
- 原九模块配置不再作为当前设置菜单，避免用户用“美化”开关启用规则覆盖。旧设置数据不删除，但不会重新激活旧模块。

## 源码生成与维护

`generate-ui-lobby.mjs` 从保留的源文件提取大厅，去掉对局初始化入口及保存代码执行入口。`isolate-rzsh-scenes.mjs` 删除排位结算程序，并将武将详情接到本体服务。两个迁移脚本均调用对应转换，重新迁移不会恢复旧业务接入。

旧模块和素材保留在目录中作为来源及资源，不代表会执行；可执行入口以 `extension.js`、`native-runtime.js` 及其明确引用为准。

## 验证状态

最终代码由用户验证。用户明确要求所有验证均自行完成后，只继续调整代码和说明，不再执行静态检查、测试、构建、打包或游戏。此前的检查不代表本次最终改动已经通过验收。

需要由用户验收的重点：两套大厅进入相同模式、国战双将、装备栏选择、护甲增减、普通/多人拼点、观星、技能响应、AI 托管、联机及切回内置外观。静态移除覆盖入口不等于所有界面交互已经运行验证。
