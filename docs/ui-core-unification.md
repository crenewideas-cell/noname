## 继续整改清单（2026-09-22，代码已改、待用户验证）

- 混搭导出：同时打包所有已选提供者，分别放在 `providers/<名称>/`，统一根入口、套装 ID 和自定义素材；兼容读取以前的单提供者包。程序仍由宿主受信任入口加载，工坊导入不执行 ZIP 中的程序。
- 联机与重连：向独立窗口传递底层原有外观配置，避免把套装临时覆盖写成默认配置；默认外观选择与提供者偏好一起提交。外观同步失败显示明确提示并保留上次已保存的外观，不中断本体启动/重连，也不标记本次同步成功。补上联机客户端 `gameStart` 的单向开局展示通知，重连不重播开局。

## 换肤要求与启动修复（2026-09-22）

换肤保留各套 UI 自己的登录、大厅、布局、卡面、武将框、按钮与动画表现；统一的是开始游戏后的规则与业务实现。不能把多套 UI 都替换成内置界面，也不能把删除原有外观当作统一业务已经完成。

上一轮 `native-runtime.js` 使用 `new URL('./', import.meta.url)` 拼接资源目录，目录可能被 Vite 当成资源路径重写并去掉尾部斜线，随后请求变成错误的 `手杀标准UIfiles.json`。现恢复从模块地址截取完整目录的方式。手杀大厅先注册，运行资源按需加载，对局皮肤在本体创建 arena 后挂载；加载失败保留所选 UI 的错误和重试入口，不再因对局皮肤初始化失败而换成内置大厅。工坊加载失败状态也不再显示为正常使用中。

展示层重新接入原有武将边框、卡牌选中边框、技能按钮、选将面板、结算背景和工具栏素材，并复用手杀座位布局、立绘轮廓。节点的规则状态、事件回调、可选项及胜负仍由本体提供。动态立绘和对局特效的独立接入见下节；显示效果尚未由开发方验证。

## 本轮补齐的展示链路

本体新增 `presentationEvents.js` 单向展示通知：开局、技能、用牌、判定、数字提示、阵亡、全屏提示、结算。通知是冻结的数据快照，不携带玩家对象、事件、规则表或继续游戏的回调；异步派发，不等待动画，展示异常不改变本体处理。单机和联机客户端结算分别在已有结果路径通知，联机直接使用服务端结果，保留本体收到的统计表，不根据不完整的客户端数据另算排行。

`native/animations.js` 使用独立 Spine 渲染器播放本地已有的开局、卡牌、装备技能、限定／觉醒／使命、伤害、阵亡与胜负动画。`generate-ui-renderer.mjs` 只提取原文件中的绘图类和字面量素材配置，不执行原 `animation.js` 后半段的技能、卡牌注册，也不加载旧动态换将或装备改写程序。

动态立绘读取本体已显示头像的武将标记，保留本体立绘作为底图；暗将、死亡、移除节点或关闭动态立绘时撤下动画。共用一个离屏 WebGL 画布，分别绘制到头像内部，保持本体遮挡与双将布局。动态皮肤菜单只列出包内确实存在的骨骼素材，选择结果保存在手杀套装自己的配置中。素材未附带或设备无法绘制时保留静态立绘，不启动其它业务实现。

普通衣橱仍使用本体皮肤服务，手杀提供独立外观。切换套装会撤下动画订阅、画布、动态立绘、统计面板、设置面板、布局及装饰。混搭套装保存全部展示提供者的清理函数，避免如真似幻大厅与手杀对局部件互相覆盖清理入口。导出套装的兼容入口也不再替换 `game.linexy`。

工坊最外层初始化失败时显示所选套装名称、错误与重试／工坊入口，保留原选择，不再把回退到内置大厅伪装成应用成功。

混搭时工坊明确指定的素材和样式优先于提供者默认 CSS，不依赖异步加载顺序；指定自定义武将框时不再额外叠加手杀默认框。

## 独立联机窗口的皮肤连续性

Electron 和 Android 联机窗口的存储、可访问文件与本地大厅分离。现在入口同时传递当前套装清单、自定义图片／字体和白名单中的手杀外观设置。Electron 使用内存中的临时凭据响应，Android 使用应用缓存文件；凭据只放在 URL 片段中，素材由本地拦截处理，不上传到 API 或对局服务器。窗口关闭后释放传递数据，联机窗口保存经过同一工坊 schema 检查的套装，进入对局或重连时沿用它。选择内置默认外观也显式同步，避免联机窗口残留上次的手杀皮肤。

`online-ui-assets.ts` 为联机客户端单独复制 `ui-skins` 展示资源：允许的大厅、装饰、动画绘图程序和图片、骨骼、字体、音频。旧九模块入口、旧技能／装备程序不在可执行文件列表内；本体规则服务器不打包这份展示目录，通用扩展入口仍保持禁用。此改动需要用户重新构建包含新展示资源的客户端，现有旧安装包不会凭源码修改自动获得这些资源。

## 当前代码边界

内置 UI 使用的 `noname` 引擎是唯一规则来源。当前工坊的墨金、霁蓝、青玉、如真似幻、手杀标准 UI 都通过本体执行选将、选牌、技能、出牌、响应、伤害、护甲、拼点、观星、AI 和胜负结算。

普通工坊套装仍由 `schema.js` 校验外观配置及资源，由 `runtime.js` 输出 CSS，不执行导入 ZIP 的程序。

手杀标准 UI 不再执行九个旧模块的 `precontent/content`，也不加载 `core-ui.js`、`junba.js`、`doudizhu.js` 或旧技能程序。`native-runtime.js` 只准备登录、大厅与资源；`native/presentation.js` 装饰本体节点，不替换原型、事件内容、规则过滤器、技能、AI 或点击处理器。国战的选将数量、势力校验、确定和取消均交给本体，不再改写选择事件。

如真似幻不再注册 `rankingContent` 或运行旧设置/皮肤扩展。大厅、模式页面、武将图鉴保留；武将皮肤、设置入口接入本体服务。

## 大厅的数据与动作

`sceneContext.js` 给大厅提供独立配置草稿和武将元数据副本。大厅拿不到本体事件、技能、角色原型、游戏循环和联网方法。修改草稿、翻页、动画或旧源程序中的辅助赋值不会覆盖本体对象。

开局通过显式入口提交当前选择的模式及本体配置表支持的子模式、人数。固定人数模式忽略源界面多余的人数字段。不支持的子模式报错。昵称和武将包启停的明确操作使用本体保存接口；其它旧配置保存在套装自己的设置中，不投影到全局配置。

这是项目内受信任 UI 的接口边界，不是任意 JavaScript 的安全沙箱。通过普通扩展安装器安装的代码扩展仍属于规则/功能扩展；不能仅改名为“UI”就保证它不修改规则。新 UI 必须使用这里的展示接口，不应引入旧扩展加载器。

## 展示迁移的可见变化

- 登录和 PIXI 大厅继续使用原素材；对局外观重新适配本体节点。
- 选将、技能交互、拼点、观星和装备选择复用本体事件与控件的行为，皮肤负责节点的布局与外观，不能由统一业务推导出外观必须使用内置样式。
- 卡面、武将框、体力、菜单、按钮、字体和指示线由展示层处理；扩展自带卡图和多属性卡面保留本体解析结果，隐藏牌不显示自定义正面。
- 旧动态皮肤加载器、技能改写型特效和旧换将/换牌程序退出运行链；动态素材改由独立绘图类使用，静态皮肤入口使用本体皮肤服务。这不是承诺旧客户端所有视觉细节像素级一致，也不恢复旧 UI 自带的额外游戏规则。
- 结算只读取本体结果及已有统计。附加统计面板不定义新的胜负、奖励或排位规则。
- 原九模块配置不再作为当前设置菜单，避免用户用“美化”开关启用规则覆盖。旧设置数据不删除，但不会重新激活旧模块。

## 源码生成与维护

`generate-ui-lobby.mjs` 从保留的源文件提取大厅，去掉对局初始化入口及保存代码执行入口；`generate-ui-renderer.mjs` 提取独立绘图类及纯数据。`isolate-rzsh-scenes.mjs` 删除排位结算程序，并将武将详情接到本体服务。迁移脚本调用对应转换，重新迁移不会恢复旧业务接入。

旧模块和素材保留在目录中作为来源及资源，不代表会执行；可执行入口以 `extension.js`、`native-runtime.js` 及其明确引用为准。
