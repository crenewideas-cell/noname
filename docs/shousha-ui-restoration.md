# 手杀局内展示恢复记录（2026-09-23）

## 原因与修复范围

手杀提供者仍然正常加载；退役旧 UI 程序后，展示适配没有完整覆盖当前本体节点的布局和高优先级样式。自身武将尺寸、操作按钮等因而呈现本体外观，卡面还优先选中了与原包默认不同的 WEBP 套图。

- 恢复原包默认 PNG 卡面、花色点数排版、身份图标、品阶龙头、手牌数图标、按钮纹理和菜单入口图。
- 修正自身武将的尺寸覆盖、延迟样式加载后的座位重排、手牌区域与窄屏布局；2～8 人座位使用原包移动布局坐标。
- 选中、可选目标与当前回合的高亮恢复原包十帧光效素材，完全由本体已有状态类驱动。
- 选将和提示继续使用本体真实节点；装饰层只添加样式与无交互的图片。后续反馈修复暂停额外的内置选择引导层，保留实际提示及核心确认、取消入口；切回内置 UI 恢复引导。菜单和排位匹配修复见 [四项反馈修复记录](ui-display-and-ranked-start-fixes-2026-09-23.md)。
- 龙头依据公开头像信息装饰；暗将与隐藏牌继续遮挡，不读取隐藏身份来选择图标。
- 没有恢复原包技能注册、选将判定、事件替换或 AI 程序。
- 对照检查发现 `copySceneData` 会执行翻译 getter（如 `qingsuan`），消耗业务随机数。展示数据复制改为读取数据属性，跳过动态 accessor；保留既有武将静态索引兼容。

## 验收边界

素材一致和当前场景运行通过，不等于所有模式、技能动画和设备都已完成原包逐场景视觉对照。原包完整运行对照尚未完成，不能将本记录视为“全场景完全一致”的证明。

当前仍沿用本体的选将内容、选择提示及工具栏结构；原包的顶部计时/牌堆信息区、阶段徽标、独立装备展示等尚未完成逐项复刻核对。原包选将刷新、计时自动操作等包含规则行为的程序不能直接重新启用；相关展示必须适配本体已有能力。

大厅仍有原先引用但当前素材目录缺失的 `zhuanpanbg.jpg`、太虚幻境官阶 Spine/图标资源；已单独记入浏览器报告的 `lobbyAssetFailures`，没有用其他素材冒充恢复。

多卡包跨两次独立启动的固定种子对照曾出现开局差异，内置 UI 对内置 UI 亦可复现；与异步牌堆初始化、卡包登记顺序有关。测试固定为标准卡包配置，并等待后台队列及随机数调用稳定两秒后再提交选将，身份局和国战对照通过；没有重置对局牌堆或修改本体规则。此结果不代表所有卡包组合都经过验证。

独立 UI ZIP 由 `node scripts/export-shousha.mjs` 导出。本轮未生成 Electron、Android 或联机客户端整包；工坊的程序使用宿主受信任入口，因此完整修复需使用更新后的宿主源码构建，单独导入 ZIP 不能替代宿主更新。
