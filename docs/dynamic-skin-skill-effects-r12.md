# R12 技能全屏特效排查

2026-09-27，公共播放器 `76a45a82cbc187aa950c`。

结论是存在一类动作路由 BUG，同时原版视频的完整演出逻辑尚未全部实现。全屏特效容器并不缺失；不能把所有未出特效的皮肤都归因于缺素材。

## 复现与修复

势魏延“狂志吞天”及其 2、3 版本使用合并骨骼，素材含 `ChuChang / DaiJi / GongJi / TeShu`。导入配置只明确登记 `gongji` 的出框契约。运行时能发现 `TeShu` 并将它绑定到技能事件，但此前只有 `source:*` 命令进入屏幕特效层，普通名称 `TeShu` 被留在头像内播放，因此大范围特效被头像边框裁掉。

公共路由现在识别同一骨骼、同一图集、已有核验屏幕动作契约的 `TeShu / Jineng`。准确动画名必须在当前骨骼中存在；不拿攻击动画代替缺失技能，也不猜测另一个模型的参数。带额外动作遮罩或特殊参数的声明不自动推广。新增 `Jineng / 技能` 事件别名。

未声明技能相机的这类合并骨骼，按整段动作的几何包络确定一次固定屏幕相机，避免默认 scale=1 把几千像素的骨骼放大到屏幕之外。后续窗口变化只调整同一相机，不逐帧追着人物缩放。原有明确 `source:teshu` 的源动作参数保留。

## 功能范围

- `bridge.js` 已监听实际游戏 `useSkill` 和 `logSkill`，路由为 skill。核心 `content.ts` 的 useSkill 流程会发出前者；`player.logSkill()` 创建的 emptyEvent 会发出后者。技能触发后使用该皮肤公开的技能动作。
- 全屏容器为独立透明顶层画面，覆盖整个窗口，不受头像裁剪，鼠标穿透；结束后释放容器并恢复主体。全屏容器不意味着素材每一像素都铺满屏幕。
- 目前通用事件只携带 skill 类别，没有完整的“具体技能 → 对应分镜 → 形态状态”绑定。势魏延三个形态仍是三个皮肤条目，没有根据技能自动切换三种形态。因此不宣称已一比一复现视频中的完整演出。
- 一些导入动画包含原画背景切片，出框后仍可见矩形边界；本轮不把这些画面标成与商业客户端完全一致，也没有改写图集补画。专用镜头资源和状态绑定仍需后续证据。
