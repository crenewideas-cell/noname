# 卡牌扩展导入与公共逻辑整合

## 导入结果

来源为 `temp/卡牌扩展包`。导入器读取顶层 ZIP 及其中的嵌套 ZIP，得到 37 条来源处理记录：导入 23 个独立卡包，去重 6 个重复版本，沿用已有士兵武将扩展，收纳 7 组素材或依赖不完整的资源。原始压缩包保留。

卡包安装在 `apps/core/extension/collections/卡牌扩展`，完整来源、处理状态、源代码哈希及资源列表见该目录的 `manifest.json`。

## 使用方式

1. 重启游戏，合并扩展“卡牌扩展”负责加载上述成员。
2. 在“卡牌”页分别开启需要的卡包，并通过“编辑牌堆”增删牌。新增成员默认不加入牌堆；已有旧开关会迁移，此后以卡牌页为准。
3. 在扩展“卡牌扩展”的配置页调整成员参数、导入卡面、冰杀卡面和 OL 序列帧特效，修改后重启。
4. 国战补充②仅在国战模式生效。有些源包本来没有预置牌堆，保留其原有设计，可由技能产生卡牌或在牌堆编辑中添加。

## 唯一公共入口

`apps/core/noname/init/cardPackRuntime.js` 统一处理卡包注册、开关迁移、模式限制、牌堆修改、配置适配、图片路径和导入素材选择。

- 内置卡包加载、扩展加载、`game.addCardPack`、`game.addCard` 和卡牌菜单都使用此模块。
- 成员模块仅提供配置、卡牌数据及各卡牌独有规则，不自行注册、不直接改动实际牌堆，不安装另一套卡包管理逻辑。
- 旧扩展的引擎覆盖、玩家原型修改和旧 UI 入口不执行；需要的规则转换为技能定义。旧十周年 UI 仅提供卡图与特效素材，通过现有公共展示事件播放。
- 名将杀的替代牌堆和活动武将的飞鸿衍生卡牌也接入公共入口。

## 修复的问题

- 关闭卡包后，旧 `cards_enable` 配置在重启时重新开启卡包。
- 同一包分批注册产生重复入堆，以及扩展直接插入牌堆绕过开关和牌堆编辑。
- 修改牌堆污染源数组，或错误去掉原包有意配置的重复牌。
- 名将杀替代牌堆不尊重卡包开关、清除其他已启用扩展的牌。
- 国战固定牌堆覆盖已注册的国战补充牌。
- 旧数字字符串配置被当作布尔开关，无法正确设置卡牌数量。
- 部分旧包的全局技能名称冲突、资源路径及旧角色数据访问方式不兼容。
- 天藏卡牌源包缺少卡图，改用引擎文字卡面。

- 核心入口 Vite 内存构建通过，输出 32 个代码块；未覆盖现有安装产物。
- 浏览器报告：`output/card-packs-browser.json`；菜单截图：`output/card-packs-menu.png`。

可用 `pnpm cards:import` 从原压缩包重新生成导入内容及安装清单，`pnpm cards:test` 执行卡包专项测试。导入器不执行压缩包内的旧扩展入口。
