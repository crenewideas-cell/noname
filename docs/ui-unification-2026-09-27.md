## 实际接入关系与排查范围

本工程的「十周年局内 UI」只负责局内展示，`builtin-rzsh` 使用如真似幻大厅并默认搭配十周年局内方案；手杀标准 UI 使用自己的登录动画和迁移后的大厅程序。因此大厅比较的是这两条实际运行路径；武将详情则直接比较千幻聆音的十周年、手杀主题，并同步复用到通用详情主题。

## 合并时修正的问题

- 详情中「全部模式禁用」初始值原先误用模式名检查武将列表；现在正确按当前武将判断。
- 取消单个模式禁用时，旧回调会触发「全部」回调并取消其他模式。公共控件现在只更新本模式，并静默同步总开关。
- 多次打开同一详情或藏珍阁不再反复登记关闭监听器和回收回调。
- 在大厅保存武将专属音乐时，核心局内音乐节点可能还不存在。现在保存配置，并仅在节点存在时切换局内音乐。
- 手杀虚拟列表中的离屏卡牌也纳入场景资源管理；离开场景销毁卡牌和 ticker。
- `fix-gallery-controls.mjs` 同步采用公共列表，之后重新生成手杀大厅不会恢复旧的逐帧全量添加循环。

生产代码及相关生成适配相较本次开始时净减少约 780 行（包含新公共模块；不计新增测试与说明）。没有简单地将一套 UI 替换成另一套。

## 验证与复现

最终结果：下面列出的 16 项模块／工坊测试及两套大厅、两种详情主题的浏览器回归全部通过，最终浏览器报告无页面异常。

本地 Vite／文件服务运行后，可以执行：

```text
node --test scripts/ui-shared-views.test.mjs
node --experimental-vm-modules --test scripts/ui-workshop.test.mjs
node scripts/ui-shared-profile-browser.mjs
node scripts/ui-shared-lobby-browser.mjs
node scripts/lobby-settings-regression.mjs rzsh shousha
```

浏览器脚本使用临时浏览器上下文与隔离配置，不修改用户保存的设置。默认地址为 `http://127.0.0.1:5174`，可通过 `NONAME_UI_TEST_ORIGIN` 覆盖。

- 公共模块：6 项测试覆盖模板、重复会话、收藏、模式禁用、自动技能、等阶、音乐，以及两种列距下的虚拟滚动与资源释放。
- UI 工坊：10 项测试覆盖方案切换、保留用户混搭、提供方清单及资源路径。
- 武将详情：十周年和手杀均检查真实控件保存、独立模式禁用、音乐配置、返回再打开以及技能页；截图与报告位于 `output/ui-unification/`。
- 样式：提取前后的相关控件计算样式对比，两主题均无差异，结果见 `output/ui-unification/css-comparison.json`。
- 公共大厅设置：两套大厅的六分页、配置保存、复用菜单以及 1920×1080／960×540 布局；结果见 `output/lobby-settings-corrected/report.json`。
- 大厅流程：武将目录、虚拟滚动、详情往返、记忆武将、藏珍阁预览／抽取／关闭回收；结果见 `output/ui-unification/lobbies/report.json`。

原有 `lobby-entry-regression.mjs` 使用较早的收藏／皮肤条假设，保持原文件。本次新增回归按当前「热门＝使用记录」与实际详情流程验证。

本次没有对所有局内玩法、所有动态皮肤素材或移动端安装包做全面回归。

## 第二轮：大厅、按钮、开始屏幕与背景元素

第一轮没有系统合并大厅本身的 UI 定义。第二轮进一步将两套实际场景接到同一组 UI 模板，而不只是合并详情页业务函数。

- `noname/ui/lobbyLayout.js`：从如真似幻的 111 个布局项、手杀的 84 个布局项中，合并 51 个完全相同的定义。包括模式选择面板及三个选项、排位段位与星标、菜单、武将信息框、将魂和官阶标记等。其余布局作为各主题的差异配置，每次创建场景均获得独立副本。
- `noname/ui/lobbyElements.js`：统一静态精灵、动态精灵、按钮事件绑定、坐标与锚点设置。两套场景原有的 29 个精灵创建函数现在只提供素材与回调，实际模板只有一份。保留手杀的非等比适配、如真似幻的等比控件适配，以及动态按钮的播放速度差异。
- 开始屏幕：统一加载标志、进度动画的 idle 创建与定位、提示文字模板和 11 条提示数据；手杀独立加载页复用同一模块。金色／白色文字、提示位置、刷新间隔、开场动画与进入时机仍由主题控制。
- 背景：统一背景尺寸计算；如真似幻继续居中覆盖，手杀继续拉伸铺满。视频背景、主题 Spine 前景及素材选择继续保留。
- 生成流程：`fix-lobby-elements.mjs` 接入现有迁移入口，重新生成时仍使用公共模板。旧代码中夹在布局定义之间的解码函数被保留，并增加启动回归以防遗漏。
- 导出兼容：手杀加载页通过宿主提供的公共模块 URL 加载，避免套装移动到 `providers` 目录后相对路径失效。
- 构建兼容：公共元素模块作为独立构建入口输出，加载页无需启动另一份游戏引擎；独立打包导出接口已通过 Rollup 检查。

已与本轮修改前的源代码逐项比较：四种屏幕比例、原始坐标及事件绑定组合共 4,680 组布局结果一致；重新生成的场景与当前文件一致，再次执行适配也不会重复修改。报告：`output/ui-elements-equivalence.json`。

第二轮最终验证：8 项元素与打包测试、6 项公共视图测试及 10 项工坊测试通过。两套大厅的武将／皮肤入口、虚拟列表、详情返回、藏珍阁和回收流程均通过且无页面异常；设置页六分页与 960×540 适配通过。加载页在 1440×810、960×540、600×900 及模拟导出目录下均通过。浏览器报告位于 `output/ui-unification/lobbies/report.json`、`output/ui-unification/boot/report.json` 和 `output/lobby-settings-corrected/report.json`。
