## 最新：按用户限定范围补齐手牌上限、特殊标记与动效

用户本次要求只完成这组剩余功能，其余由用户实际测试后反馈。本节为最新状态；下方旧章节中的“手牌上限、法箓/残玺、目标/濒死效果待迁”已由本节更新，不表示重新开启完整像素一致或设备验收。

- 手牌区域显示现有手牌数及本体 `getHandcardLimit()` **最近一次既有调用的返回值**，支持 0、∞ 和超限红色。未计算过时显示“—”；提示文字明确其含义。UI 不额外调用该方法、不轮询 modifier、不复制上限计算规则。缓存随本体正常计算更新、切换 UI 保留、玩家重置时清除。这是复用已计算结果的展示，不能声称是任意规则变化后立即重新计算的实时上限。
- 法箓四花色、残玺六势力使用原图，直接装饰本体标记节点，保留点击、悬停说明和移除行为；往生/向死/取消等例外标记不误套六势力贴图。武将隐匿时撤除附加贴图，移除标记和卸载时清理。
- 界/神/SP/TW 角标读取原包静态前缀映射，仅给已明置主将显示，不执行翻译 getter，不推测未明置信息。
- 过河拆桥的斧头/桥两个动作、顺手牵羊的目标与 600ms 回返动作及对应音效，消费本体通过排除/无效目标检查后的展示通知。原牌效、目标选择、结算和时序不变；600ms 仅为可取消的 UI 定时器。
- 濒死“救我”跟随玩家节点循环，本体濒死进入/退出发送公开展示状态；恢复、阵亡、移除节点、关闭特效及卸载都会停止。中途切换 UI 可恢复仍有效的濒死展示。新通知支持展示广播与录像分发，旧录像没有通知时不伪造效果。
- 提供者新增 `extras.js`，已加入受信任文件清单。仍要求本次工程宿主；ZIP 不是任意旧版客户端补丁。

## 核心逻辑边界

本体仍使用原有的伤害、护甲、回复、技能、洗牌和 AI 路径。仅给既有 `$damagepop` 增加可选的公开展示数据：原因、数值、是否虚拟伤害。该数据随原数字提示的广播和录像记录传递；旧调用与旧录像没有该数据时继续显示原有数字，不让皮肤猜测伤害原因。

提供者只接收冻结的数据副本，不接收事件对象、规则注册表、选择条件或继续游戏的回调。动画异步播放，不等待动画结束。源包的技能触发器、装备效果、事件替换及业务覆盖代码未导入。
