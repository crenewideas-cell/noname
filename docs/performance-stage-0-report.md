## 2. 场景和统计口径

精简组只有 standard 人物/卡牌；默认组使用仓库登记的默认扩展，实际有 18 个启用扩展，列表在每个样本中。二者是不同功能配置的对照，**关闭扩展不算优化，默认组也不是用户实际存档**。

均为隔离的合成双人身份局、固定随机种子、确认 GPL、跳过教程、自由选将、10 人/页、显示全部人物、关闭出牌自动确认。脚本使用真实控件选择身份、打开自由选将、切到第 2 页、搜索并选择曹操、确认、等待自己首个合法出牌事件、选中并取消手牌，逐项断言状态。

“冷”同时表示新上下文、清 HTTP 缓存及首次登记；“热”保留上一轮游戏写入的配置。因此，首次登记与恢复配置和缓存同时变化，**冷/热差值不能归因为纯缓存收益**。精简初始候选数从 32 变成 3，默认组从 1143 变成 9，就是配置初始化影响的实证。Vite 依赖磁盘缓存和操作系统文件缓存保留，第一轮服务器导航单独标记。

每格为毫秒 `p50 / p95`，每个配置/冷热门类 n=20，nearest-rank；所有原始样本纳入，未删除慢样本。第 1 对开启详细 CPU trace，存在录制开销，字段 `traced` 可筛选；去掉首对只剩 19 个样本，不能另报为完整 20 样本 p95。以下数值是受测条件下的描述统计，不是对其他设备的保证。

## 4. 请求、主线程与重点方向

Resource Timing 中，大厅就绪时已完成资源传输量中位数：精简冷 26.7 MiB、热 2.9 MiB；默认冷 144.4 MiB、热 132.4 MiB。到流程结束默认冷约 368.9 MiB、热 142.9 MiB。这是 **Vite 开发环境** 的完成资源量，含开发转换代码及扩展媒体，不是生产包大小，也不含文档/未完成请求；HAR 另外保留实际请求及可得的传输字段，缺失字段计入 unknown。

实测资源包括：`xinwei.woff2` 7,854,084 字节、`shousha.woff2` 4,819,904 字节；默认扩展人物图 `清瑶葭绮/members/渐意新生/xxy_yingyue.jpg` 达 17,254,585 字节，`xxy_lianyinshuang.jpg` 达 9,503,357 字节。阶段 1 应同时处理字体使用范围、实际可见人物缩略资源及正确服务上的传输压缩，保持完整素材和字形回退。

默认组虽然每页显示 10 人，实际人物库按钮达到 2551/2552 个；初次选将时全页约 12841 个 DOM 节点。精简组人物库只有 33 个按钮。阶段 2 的首要验收是“按页创建实际节点”，同时验证搜索、跨页状态和扩展兼容；只隐藏按钮无法控制创建成本。

观察窗口内，默认冷每次长任务数中位数 9，单次最大长任务的 p50 为 657 ms、p95 为 1220 ms；默认热对应 7 个、215/355 ms。精简冷为 2 个、80/101 ms；精简热观察窗口内多数未记录到长任务。观察器初始化前的静态依赖执行可能未覆盖，未记录不等于整个导航没有长任务。

首轮默认冷 CPU trace：`onfree` 的 `loop` 回调累计约 805 ms，单次约 472 ms；UpdateLayoutTree 累计约 1528 ms，单次约 203 ms；Layout 累计约 459 ms，单次约 250 ms。各类时间可能嵌套，不能相加。该轮 card 点击回调累计仅约 3.7 ms，不能把约 3.4 秒交互等待全部归因于手牌函数。阶段 3 应结合人物节点、后台 `onfree`、渲染和资源竞争处理，避免把工作简单推迟到用户操作时。

默认第 2 冷样本中，运行包等待约 2219 ms、`extension.import:活动武将` 约 1616 ms；这些异步跨度包括获取/执行等待，不是纯函数 CPU 耗时。编译缓存已有命中记录，不能据此删除缓存或泛化为“所有技能编译是主要瓶颈”。

普通生产构建复测在实际产物 `noname/game/index.js` 初始化时报 `ReferenceError: Cannot access 'GamePromises' before initialization`，120 秒内未出现大厅，首轮记录 3 次文档导航（包含 JIT 自动刷新）。因此生产大厅、选将和交互指标均为**未测成功**；未继续重复 20 次同类失败，未提供虚假的生产 p95。该渠道是普通 core 构建及测试静态服务器，不是 `build:online` 或真实部署。

补充核验了对话中断前已完成的无埋点对照：`02-16-45-201Z` 隔离构建将 4 个埋点文件恢复到 HEAD，构建退出 0；`02-18-00-067Z-production-minimal` 以 `--collector=off` 运行，仍在 120 秒大厅等待中失败，记录相同 `GamePromises` 初始化异常。接续时逐文件核对这 4 个快照确与 HEAD 字节相同。结果说明该启动故障并不依赖本次性能埋点；未据此宣称已定位完整循环初始化链或找到修复。此结果属于当时源码快照，不能代替当前工作区的生产复测。
