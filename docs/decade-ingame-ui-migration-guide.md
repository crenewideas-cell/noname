## 4. 纯展示层强制契约

### 可以做与禁止做

| 可以做 | 禁止做 |
| --- | --- |
| CSS、图片、字体、布局、卡面、装饰节点、动画、展示音效 | 注册或修改技能、卡牌规则、AI、事件内容、结算或联机业务 |
| 读取本体已公开的可见状态或展示快照 | 写玩家体力、手牌、装备、身份、技能、事件状态、轮次或胜负 |
| 显示本体产生的候选、可选状态、确认与取消状态 | 改 filterButton/filterCard/filterTarget、选择数量、自动选择或事件结果 |
| 保留本体操作节点和处理函数；通过正式动作接口提交用户意图 | 覆盖 ui.click、Player/Card 业务原型、lib.element.content 或 game 方法改变行为 |
| 订阅用牌、伤害、开局、技能、阵亡、结果等展示通知 | 用 lib.skill 注册“只做特效”的全局技能；在皮肤中暂停、推进、重做或结束游戏事件 |
| 本体决定可显示内容，皮肤绘制效果 | 读取隐藏身份、手牌或牌堆来推导效果，泄露非公开信息 |
| 元数据保存骨骼、贴图、坐标、缩放和时长 | 在 JSON 字符串、骨骼事件、回调中夹带可执行业务 |

转发用户操作是展示层的必要连接，不授权 UI 实现规则。任何模式继续运行都不能依赖某个皮肤。尽量只向渲染器暴露只读展示数据、挂载节点和白名单动作，不将完整可变引擎对象传给来源脚本。

### 缺少本体能力时

1. 先查现有业务入口和展示通知，优先复用。
2. 缺展示通知：在本体正确时点增加通用、非阻塞、只含可见数据的通知，不在规则判断中加入皮肤名称。
3. 缺公共交互能力：在已有职责模块实现，所有皮肤共用，并为实际规则变更补测试。
4. 源 UI 附带本体不存在的玩法：记录差异，不随迁移擅自引入规则，不把旧规则整份挪到本体。
5. 禁止新建“UI 专用业务服务”，通过改名、移动或代理包装伪装分离。

### 动画和生命周期

- 引擎不等待动画资源、结束回调或 UI Promise；动画关闭、超时、失败不得影响结算。
- Spine/Canvas/PIXI 只用于绘图；不要执行源 animation.js 中的技能注册、装备改写和游戏循环。
- 不通过 window.decadeUI/app 等可变全局对象共享多套皮肤的业务或状态。
- 卸载释放订阅、观察器、定时器、RAF、音频、画布、WebGL、临时样式、节点、Object URL 和异步任务。
- 已退出皮肤的异步任务不能重新挂载；重复应用不能堆积节点、订阅或音频。
- 可以沿用重新载入生效，不要求正在进行的对局中热切换整套 UI。
