2026-09-26。收尾入口：`output/dynamic-remediation/20260926-r01/idle-masks-r05/idle-masks-close.json`。本轮延续 G2/G3，冻结4934、优先4895、原37模型对应39皮肤暂缓、删除0；没有安装到正式皮肤包，没有逐条最终验收。

## 修复依据

用户三条文鸯反馈和两张神荀彧截图揭示的是不同的公共缺陷，不能用统一放大或删遮罩解决。

| 现象 | 定位及修复 |
| --- | --- |
| 破云翔宇2顶部灰带 | BeiJing 图集的 bgck 本身是完全不透明的 RGB80 平面。只在相机测量时排除完全均匀的中性色背板，以包含人物头部的绘画不透明区域裁边；源纹理、附件和最终绘制保留。 |
| 云涯文鸯只见马、人物被裁 | 数字附件缺少脸部语义，原算法只看背景。采样主层一个待机周期的实心几何包络，主体超出背景时改为完整包含；大预览使用场景比例，列表仍保留原画框。真实透明区域保留。 |
| 骁勇金衔异常放大 | 去掉由 daiji2 文件名、十周年标记与比例推断出的第二次放大。显式图层配准、composition 和场景变体仍优先。 |
| 神荀彧为汉建安主体偏右、被裁 | 多人构图按最大脸部选择到配角。改为优先身体附件占比明显的命名分组，再比较脸部大小。没有按皮肤名、角色或 ID 写分支。 |
| 神荀彧龙镇天清系列人物偏离中央、头冠被裁 | 原算法只用脸部定位横向中心，再按背景裁边。用户明确指出第二图重点是人物未居中。现在以主角包络中心作为画框水平中心，背景不对称和旧裁切偏移不能覆盖主体中心；保护脸部和附近头冠的一周期包络；固定相机，不逐帧追脸；窗口比例改变时再次约束。匡汉延祚、爆料皮肤的对应骨骼复用相同素材，未将名称推测写成用户确认。 |

公共实现位于 composition、idle-framing、player。新相机测量限于具有完整 Skeleton/AnimationState 接口的3.6/3.8/4.0后端；混合后端的栅格代理保留原路径，避免把代理当骨骼访问。存在活动 clipping 时不以未裁切网格包络代替可见轮廓。剩余图层比例回退仍需最终分类回归，本轮不宣称所有自动配准均已认证。

旧待机条目可直接使用公共修复，不必逐条加比例。源动作候选新增显式 `protected-idle-artwork` 取景政策：动作记录、身份与外部屏幕坐标保留，待机走艺术画面坐标。未显式声明动作时选择稳态待机，不循环播放首项 ChuChang；每层保存 resolvedIdle，单次动作结束和重置返回该层待机，显式返回动作仍优先。旧候选政策没有批量改写。

头像与屏幕特效继续分离。大预览只在现有 layoutPreview 中调整画框比例，不写 hub.framing 或存档；同时修复暂停状态下 renderer.resize 清空画布后没有重绘的问题。

## 遮罩缺陷

PIXI 缓存的 clipping 图形在附件切回 region/mesh 时仍参与分组，导致额外裁切；裁切槽位继承旧 region 的骨骼变换会重复变换世界顶点；绘制顺序变化、嵌套剪裁及直接写入 children 的占位节点又会留下错误分组或累计引用。

source-masks 在 state.apply 后、显示节点生成前处理隐藏附件及缓存状态。更新后按骨骼 drawOrder 重建裁切分组，活动剪裁结束之前忽略内嵌 clip，结束槽位即使隐藏也仍然结束裁切；缓存图形与附件/deform引用在 finally 恢复。只移除适配器拥有的槽位及占位引用，保留其他子节点。没有全局禁用 mask。

实际3.8.99/4.0.56浏览器夹具验证：clip→region→clip、凹多边形、drawOrder变化、加权顶点、deform、嵌套与恢复；每后端1000次更新后槽位引用没有增长。旧代码 clip→region 为6400像素，正确几何为12800；新代码一致。外部 clip/clipSlots/disableMask/outcropMask 的未支持契约没有因此放开。
