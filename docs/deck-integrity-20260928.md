# 牌堆通用逻辑复核（2026-09-28）

按最新要求，先核实故障，再保留对应修复；没有复现出问题的武将自身规则不改。本报告替代上一版包含专属牌池方案的报告。

## 已撤回

- 恢复名将杀卡牌定义、卡包入口、诸葛亮技能和 arenaReady 的本次改动。
- 删除本次新增的 tacticsPile.js 专属牌池。
- 撤回清瑶成员的单独联机标记；后续仅在资源入口声明公共仙牌的通用 requiredGroups 元数据，并跟踪该入口文件。
- 删除核心中的具体势力标记判断，撤回合并包的额外联机成员筛选。
- 保留工作区原有的其他武将、皮肤和资源修改。

核心没有新增武将名字或势力名字分支，没有每武将专属牌堆或技能生成牌的回收机制。势力资源由提供它的卡牌声明，任意来源的同势力武将共用。

## 用户反馈后的纠正

用户在身份模式选不同武将时均出现 `武将依赖的卡牌 changshezhen 未加载或不支持模式 identity`。用现有阵法卡定义复现了完全相同的异常：长蛇阵声明 `mode: ["guozhan"]`，此前新增的检查却把已启用来源的全部卡牌当成必须可用，导致一张不兼容牌中断整局。该检查是本次改动引入的回归，已移除。

现在先按卡包和单卡的模式兼容性筛选依赖；身份模式正常排除阵法牌，国战保留阵法牌，其他合法公共牌继续加入。未注册卡牌沿用正常组牌的排除规则，不抛出阻断开局的异常。未改动具体武将或长蛇阵自身规则。

另已复现跨来源遗漏：只启用红楼幻境的仙势力武将、禁用清瑶武将包和公共卡包时，旧版同源规则补入 0 张仙牌。现通过卡牌的 requiredGroups 声明关联选中武将池及场上势力，匹配任意来源的武将；仅补该势力的牌，不连带开启混合卡包中无关的牌。来源元数据独立保存，不因其他扩展抢先注册同名定义或分片注册而丢失。

## 实际复现的故障

### 再次反馈：独立启用绛珠仙子时缺少仙牌

上一轮浏览器用例预先加载了清瑶牌源，只验证了“牌源已加载、开关关闭”的情况，未覆盖整个牌源扩展未加载。因此上一轮测试不足以证明绛珠仙子独立启用时能获得仙牌。

本轮增加通用共享资源声明及按势力加载入口。引擎根据选中武将池/场上武将的势力解析声明，在开局注册完成后和大厅实时启用扩展时，加载所需卡牌定义、技能和原始公共牌表；不打开牌源扩展的武将开关。不为单个武将建立牌堆。公共仙牌资源入口与原扩展复用同一个工厂。

真实浏览器验证：只加载红楼幻境、完全不加载清瑶武将扩展，实体牌堆得到原有 8 张公共仙牌，相关装备技能也可用。再加载原牌源扩展，仍只有 8 张。无相关势力时不加载资源；重复请求合并为一次加载。一万个同势力武将共用一份原牌表。去重后保留首个牌源注册的全局规则，避免卡牌存在而规则停用。

共享加载继续遵守资源的模式及联机兼容声明。当前仙牌源没有声明联机支持，本轮没有将该离线牌源强行接入公共托管对局。加入牌库也不等同于保证某个回合摸到仙牌。

### 诸葛连弩 AI

浏览器使用真实 Player、Card 和引擎的 order/value/equipResult 判断复现：原 AI 将连弩排在杀之后；已使用杀时，连弩估值固定为 10，不再随剩余杀的数量变化。

现在有可获益的合法攻击目标且手中多张杀时，连弩优先于杀装备，保留价值随剩余杀增长，同时影响弃牌和换武器判断。已有连弩时，验证了两张杀加高基础价值仙界武器的场景：不会为了换武器提前放弃连杀。没有获益目标时仍降低估值。临时递归标记在 finally 中清理。

### 前一轮基线复现

使用修改前基线 5a09a0e87 中的模块，以只读方式加载到独立 Node 实例，与当前实现对照。真实扩展作为诊断输入；正式回归使用任意来源名，避免只验证两个示例。真实资源在修复后的同一注册流程中得到完整 8 张公共牌。

## 通用规则

1. 使用现有导入来源信息关联武将包与卡包，适用于 package 注册和 game.import 分包注册；无须逐个武将配置。
2. 被选中的武将包关联同源卡包中模式允许的公共牌；卡牌还可通过 requiredGroups 声明势力依赖，跨扩展匹配武将势力。场上角色也参与解析。多个武将共享同一份卡包贡献，不按武将数量增加牌数。
3. 依赖优先于该公共卡包的独立关闭、原始牌堆删项和单卡禁用；关闭对应武将包、且没有场上依赖时，卡牌开关恢复独立生效。菜单说明此规则。
4. 没有 list 的技能生成牌仅保留定义，不自动加入公共牌堆。未关联武将的卡包维持独立开关。
5. 先执行模式/乱斗牌堆处理，再核对依赖和扩展贡献、过滤不合法牌、补牌、生成实体卡。按元组数量补足，重复执行不累计注入；不同扩展的贡献合并计数。
6. 联机使用房间选包，忽略加入者的本地选包偏好；重建房间牌堆先清空旧牌堆和场上依赖记录。全局卡牌技能及子技能的触发、数值修正跟随实际启用状态。
7. 不支持当前模式或联机的卡包、单卡按正常规则过滤，不因同源扩展中混有不同模式的牌而中断开局。没有给未声明兼容的扩展自动添加联机能力。
8. 按最初要求默认开启现有补牌功能：新配置、已有配置的一次性迁移和托管房主配置均覆盖；迁移后再次手动关闭会被尊重。原比例算法、上限与只补不删的规则保留。

按来源关联意味着同一扩展内模式允许的公共卡牌随武将资源一起生效；跨来源势力关系由卡牌元数据声明。这些规则不猜测技能函数中的字符串，也不改写武将技能。资源提供扩展必须已安装并加载，声明不能自动下载或加载缺失模块。
