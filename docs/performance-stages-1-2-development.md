## 阶段 2：人物目录与搜索

### 接入范围

`ui.create.characterDialog("heightset", "paged")` 显式进入新目录。已接入身份局和斗地主的自由选将；只读人物目录在启用分页设置时也走新目录。关闭分页设置、`characterx` 分支人物、自定义分组、卡牌目录、未经适配的其他模式/旧扩展继续保留完整按钮接口。普通开局候选与技能 `chooseButton` 未改为局部候选。

### 数据与兼容接口

`ui/characterBrowser.js` 持有人物 id、过滤条件、查询结果、页码、选中 id、禁用原因和焦点 id。先应用名称/技能搜索、首字母、势力、收藏/最近与武将包过滤，再切当前页创建按钮。页大小沿用用户设置；离页未选按钮释放，已选按钮暂存以桥接引擎的 `ui.selected.buttons`、结果顺序和旧 Button 引用。DOM 保留量按“当前页 + 跨页已选项”计算，并非零屏外节点。

`dialog.characterPager.buttons` 是当前页与已选按钮的引擎视图；`selectedIds`、`disabledReasons` 提供状态；`page`、`pageSize`、`totalPages`、`total` 提供目录指标。`game.check/uncheck` 适配该视图，并在翻页后重新判定合法性，不复用过期按钮缓存。已选项有跨页取消入口；支持键盘 Enter/空格、PageUp/PageDown，控件阻止游戏快捷键冒泡。

`dialog.buttons` 仍是完整真实 Button 数组：旧调用第一次读取时物化全部按钮，随后该目录进入完整 DOM 兼容模式。AI、随机候选获取、全选、复杂自定义选择，以及强制选择但当前页无合法项时也使用完整集合。这样保留旧契约，但触发兼容路径就不再具备严格分页的节点收益。最终验收必须同时记录是否物化，不能只报告屏幕可见数量。直接给 `dialog.buttons` 赋值会退出分页控制器，由原调用方接管。

普通分页目录关闭时释放未选节点和对应缩略图可见性观察，保留结果所需的已选 Button；重新打开恢复当前页。完整 DOM 兼容模式保留旧调用方的节点引用。人物池仍按创建目录时收集，新增人物需要重新创建目录；已有候选的技能/译名改变会在下一次搜索刷新。

### 搜索

`util/characterSearch.js` 按目录需要读取人物名称、简称、拥有技能和技能译名。去掉原有 `queueMicrotask` 全技能扫描。索引按约 4 ms 批次让出，返回匹配 id；16 条查询 LRU，人物列表/顺序、文本、技能列表和技能注册状态变化均使相关缓存失效。打开目录清理索引，关闭取消任务，新搜索覆盖旧搜索。

正则匹配放入临时 Worker，3 秒上限，结束/关闭/新查询时释放 Worker 和 Blob URL。Worker 不可用或 CSP 拒绝时，普通名称和简单锚点查询保留分批回退；复杂正则显示明确提示。非法正则保留原结果并显示错误。旧全量目录也采用这个搜索器，旧 DOM 和筛选接口保留。`setTimeout` 的预算只能约束批次之间，实际耗时仍需统一验收。
