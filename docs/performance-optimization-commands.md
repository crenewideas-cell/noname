# 性能优化执行命令集

配套手册：`C:/pxlngu/projects/noname/docs/performance-optimization-guide.md`  
工程目录：`C:/pxlngu/projects/noname`  
用途：将下面的文字命令发送给开发助手，按阶段实施、验证和记录性能优化。这些是对话指令，不是 PowerShell 命令。

## 使用方式

第一次发送“阶段 0”，完成后发送“继续下一阶段”，也可以明确指定某一阶段。每次只执行一个阶段；需要补完前置工作时，在该阶段内先处理必要前置项。

阶段编号 0–8 对应指导手册的 PR-0–PR-8，仅表示开发交付批次，不自动意味着创建、推送或合并 GitHub PR。

如果换了对话或工作目录，使用下方带完整路径的命令，确保能找回手册和进度。无需把整个手册重复贴进对话。

**当前阶段 1–3 实现已落地，待最后统一验收；阶段 4–8 未开发。** 最新状态以 `docs/performance-optimization-progress.md` 为准。

**2026-09-14 用户覆盖指令：先完成所有步骤开发，再统一测试。** 以下各阶段原有“运行测试/构建/采样”和“先测量”的要求暂缓，保留为最终验收清单。本轮及后续开发轮次不自动执行测试、lint、构建或浏览器验收；未验收不阻止进入已授权的下一开发阶段，也不得标记为验收通过。每次仍仅推进用户当前指定阶段，完成后更新进度。

## 所有阶段共同遵守的执行约定

以下约定随每条引用本命令集的命令一起生效。

1. 先读取指导手册、本命令集、已有进度记录和适用的仓库指引，并检查当前源码、Git 状态及上次交付证据。手册为分析时快照，发现源码已变化时先更新判断，不重复实施已完成优化。
2. 本阶段命令授权实际开发、必要的本地依赖安装、隔离测试、运行本地服务、性能录制和本地构建；直接完成实施与验证，不停留在计划或静态建议。构建、浏览器和服务使用可识别的测试目录/会话，结束后清理本阶段启动的临时进程。
3. 保留既有玩法、模式、技能语义、扩展兼容、用户启用设置和存档；测试使用隔离浏览器配置与数据副本。不得把永久关闭扩展、删存档、跳过规则或隐藏功能算作优化。尊重工作区已有改动，不覆盖不属于本阶段的工作。
4. 以手册为依据选择具体方案。对尚未实测的热点先测量，允许用证据调整实现方式，并记录理由；不要为了落实建议而实现没有收益或改变语义的改动。
5. 保护旧式 step 标记、函数源码反射、跨步骤变量、扩展注册顺序、同步图片接口、动画状态边界、配置事务和联机 build 一致性。相关优化必须有针对性回归，尤其要在构建产物上验证构建改动。
6. 每阶段执行相关功能回归和同条件性能比较，保存执行命令、环境、样本数、原始证据与结果摘要。未测量填“未测”，不填 0，不把目标预算写成实测结果；不能通过降低预算或只挑最好样本宣布通过。
7. 缺少网址、真机或账号时，先完成不依赖它们的本地工作，明确列出待验项；涉及其结果的验收保持待验，不把桌面模拟当真机，也不将本地结果当作线上结果。需要用户提供必要信息时一次问清。
8. 常规可逆的开发选择自主处理。本命令集不包含线上部署、远程推送、PR合并或向他人发送消息；这些操作另行明确安排。本地形成完整可评审结果，不为未要求的发布操作提前中断开发。
9. 每阶段更新进度文件，写清完成项、修改文件、实测前后值、验证结果、剩余问题、兼容/回退方式和下一条建议命令。因环境无法验证时，状态写“实现完成，待验收”；存在失败时写清失败，不标记为完成。
10. 一条阶段命令做到该阶段结束后停下，不自行进入下一阶段。若本阶段较大，可在阶段内分多个实现步骤持续完成，不因步骤多而只交付一个方案。

## 进度文件最低内容

首次执行阶段 0 时建立，后续每阶段持续维护：

| 记录项 | 要求 |
| --- | --- |
| 源码与环境 | commit/工作区版本、构建渠道、实际测试地址、浏览器与设备、扩展配置摘要 |
| 阶段状态 | 未开始 / 进行中 / 实现完成待验 / 已验收 / 受阻；每个状态附证据或原因 |
| 已实施内容 | 文件与行为变化、与手册方案的差异及理由 |
| 正确性验证 | 命令、时间、退出结果、覆盖范围与失败项 |
| 性能比较 | 条件、样本数、优化前后指标、预算、HAR/trace 路径；缺失值明确标未测 |
| 剩余工作 | 下一项可执行任务、需要的外部输入、是否阻塞后续阶段 |
| 回退办法 | 本阶段开关或明确文件范围，避免覆盖用户其他工作 |
| 下一条指令 | 可以直接复制发送的下一阶段或继续当前阶段命令 |

这样每次发送阶段命令都能接续已完成工作，不依赖聊天历史完整保留。
