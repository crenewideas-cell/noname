# 手杀标准UI · 独立界面套装

这是当前工程的独立 UI 提供器。唯一扩展入口为 `extension.js`，内部模块不是独立安装的扩展，不进入宿主的扩展列表，也不需要玩家逐个启用、更新或管理。

## 迁移内容

- 启动页使用原加载背景、Spine idle 动画和提示文字；首次升级读取当前套装选择，此后由首屏缓存直接显示。登录及大厅素材就绪后再撤掉加载画面。

- 登录使用原版 HTML、CSS 和三层 Spine（背景、人物、发光开始游戏按钮），包含版本、帐号栏、更换昵称、公告、客服、社区、单机入口、适龄标志、底部标识和选区装饰。账号栏接入当前项目的本地昵称；不连接旧客户端账号服务。
- 大厅直接提取原版完整 PIXI 场景代码：档案、等级、VIP、货币展示、左右侧栏、经典/排位/自由/至尊入口、活动、底部功能、原版模式页面、主题/头像选择、武将页面及原有本地交互。
- 对局使用原版十周年 UI 与手杀 UI 的节点构造、操作区域、技能按钮、手牌、装备、标记、动画、暂停菜单及相关交互。
- 身份场使用原版 `junba.js` 的全屏选将、主公信息、座次、逐张换将及次数展示；斗地主、2v2 和其他选择弹窗使用原包对应程序。
- 结算采用原版手杀 MVP 程序，包含统计、评分及 MVP 页面。
- 内含皮肤切换、千幻聆音、标记补充和电脑适配的界面程序与本地资源。动态皮肤、皮肤详情、语音、收藏、标记说明及鼠标操作不再只是替换静态图。
- 九个 UI 模块的资源保留原目录关系，包括可选主题、登录动画、卡牌变体、音频、字体和骨骼素材。文件清单为 `files.json`，来源统计为 `NATIVE-SOURCE.json`。

## 独立封装

内部模块位于 `original/` 和 `native/`。内部扩展探测通过兼容接口完成，元信息使用不可枚举的私有映射，不写入宿主 `lib.config.extensions`，不注册到 `lib.extensionMenu`、`lib.extensionPack` 或扩展目录索引。

用户配置集中存储于 `ui_workshop_shousha_settings`。登录页的本地状态使用 `noname-shousha-native:` 前缀。套装设置按“登录与大厅、对局与卡牌、操作与技能、选将、结算、皮肤、标记、鼠标与触控”分组，入口在大厅右下角或手杀标准 UI 自身的设置页。

`native-runtime.js` 负责脚本顺序、传统脚本全局变量、资源路径、当前引擎角色/卡牌类、手牌缓存、装备观察器和源扩展回调式初始化的适配。选将及界面程序接入当前引擎；旧引擎启动、事件循环和联机连接不被替换。

联机房间通过当前项目的房间服务打开。源包没有附带的玩法及远端服务不会凭空变成可用功能；未安装的专属模式会明确提示。原界面里本来用于展示或本地模拟的入口仍保持这一性质。

## 工坊、导出与预览

工坊中选择“手杀标准UI”，点击“一键使用所选套装”。来回切换直接引用同一个套装 ID；旧的完全重复记录由工坊去重迁移整理。

登录预览运行原版登录渲染程序；大厅、选将和对局提供标明来源的原版参考图，完整交互在应用后呈现。参考图来自用户提供的截图，并非此次迁移后的运行截图。

完整资源超过旧的 512 MB 限额。该提供器支持最多 3 GB、24000 个文件的 ZIP：导出使用 Blob 分块，导入按目录和所需清单读取，不把全部界面资源转成巨型 JavaScript 字符串。工坊导入不执行压缩包里的任意脚本，仍引用本工程内置的提供器。

直接从项目内资源导出（无需参考目录）：

```powershell
node scripts/export-shousha.mjs
```

开发者只有重新从外部参考工程迁移时才需要 `node scripts/migrate-shousha-native.mjs --source="<参考工程>/resources/app"`。它不属于运行或构建步骤。仅更新程序转换和清单可以使用 `--code-only`；同步源文本资源可加 `--refresh-text`。旧的 `migrate-shousha.mjs` 属于已被替代的素材适配版本，不用于本版重建。

`temp` 仅为一次性参考来源，已由仓库忽略。实际程序、动画、图片、音频与字体全部位于本套装的 `native/`、`original/` 等目录；删除参考目录不会影响运行、构建或导出。源版本信息仅保留在 `NATIVE-SOURCE.json` 作为来源记录。

导出文件：`dist/ui/手杀标准UI-UI套装.zip`。没有导入源 exe、旧引擎、Home、UserData、账号密码或缓存。

按用户要求，本轮未执行测试、构建验证或浏览器验收，交由用户实际运行验证。
